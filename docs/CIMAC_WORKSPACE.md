# CIMAC 独立园区工作区

建材城的现有业务入口和办理内容集中在独立园区工作区，不新建第二套客户、合同、资产或账务事实。中文 `/cimac`、法文 `/fr/cimac`。SACSI 保留工作区切换，普通业务页排除 CIMAC；原有明确建材城深链接按当前用户可见的实际归属跳转，不依赖客户姓名猜测。

## 路由与职责

| 页面           | 路径                                              | 事实来源                                                  |
| -------------- | ------------------------------------------------- | --------------------------------------------------------- |
| 园区首页       | `/cimac`                                          | 当前授权 CIMAC 资产状态、关联客户数；关注项不是已分派工单 |
| 商铺地图       | `/cimac/map`                                      | 保留原商铺分布、搜索、正式合同与预留资料核对              |
| 招商与客户     | `/cimac/customers`                                | 既有项目范围内客户目录，搜索、楼栋、关系筛选与分页        |
| 客户详情       | `/cimac/customers/[id]`                           | 业务总览、合同与交付、账务与收费、事项与资料              |
| 园区资产       | `/cimac/assets`                                   | 商铺、公寓、仓库等已登记资产，按状态筛选与分页            |
| 资产详情       | `/cimac/assets/[id]`                              | 资产概览、合同与客户、物业与表计、文件与记录              |
| 收费与资金     | `/cimac/finance`                                  | 先选择客户，再查看该客户总账，不自动选择第一位客户        |
| 合同与履约     | `/cimac/contracts`                                | 现有建约、生效、退租、打印、租金纠正与收款业务            |
| 原币合同收款   | `/cimac/contracts/[id]/collect`                   | USD/CNY 原币流程，不自动折算                              |
| 收支流水、应收 | `/cimac/finance?kind=ledger`、`?kind=receivables` | 锁定园区项目的筛选、分页、核查和导出                      |
| 经营分析       | `/cimac/reports`                                  | 园区原始流水及应收口径，原币分别展示                      |
| 历史出售合同   | `/cimac/contracts/history/sales/[id]`             | 只读历史档案，不因目前只租不卖删除旧事实或开放新销售      |

法文页面一一对应。合同、客户资料和资产运行条件在本工作区办理；复用底层内容组件与原子操作，不嵌套旧路由页面。共享身份资料修改有影响范围提示和版本检查，保留原有写权限与审计。

## 边界

- 每个服务端页面独立验证 Supabase 用户、数据库角色和当前账号项目 RLS。仅 admin、boss、finance、rental_sales 可进入；这些角色仍须已有 CIMAC 项目权限。不存在或未授权项目不回退到其他项目。
- 账务限现有 admin、boss、finance 读取；boss 只读，admin/finance 的写入还需既有 RPC `canWrite`。rental_sales 不读取、序列化或展示客户总账入口。新页面不授予任何数据库权限。
- 服务端 React `cache` 仅限当前请求，不以进程级缓存共享账号范围。首页/客户总览/资产详情不预加载全客户财务历史，仅客户 `tab=account` 懒加载现有总账 RPC。
- 项目范围以唯一活跃 `CIMAC` 项目解析。对象、楼栋、返回链接、分页和 tab 都验证；异项目对象、无效 ID、重复查询值及未授权参数失败关闭。资产轻量索引精确计数并有 10,000 条上限，不能静默截断为完整库存。
- 客户关联是登记业务关系，不是产权证明；建设、占用核验、交付、开业相互独立。没有独立资料的交付/开业/通用工单不由合同或付款推断，也不使用样板虚构客户和任务。
- 最近资产更新仅来自首页当前索引，不是完整审计；原始审计仍从现有授权审计入口查看。
- 资产的表计页链接对应客户已有抄表分区；未加载读数不表示零用量。通用物业工单、独立交付和开业流程仍待建设，不宣称已完成。园区经营分析提供已有财务统计，不冒充完整园区经营数据模型。
- 公司级审计继续使用 `/settings/audit-logs`；原全公司关联核对迁入明确标注的 `/settings/finance-reconciliation`，保留原角色边界。项目页面不把公司级结果展示成该项目结果。

## 历史与财务保护

本轮不新增数据库迁移，不写入生产业务记录，不重算、覆盖或搬迁历史账务。`CimacAccountContent` 复用共享的账单、收款核销、水电抄表、规则约定区块；旧 `/finance` 默认锁定 SACSI，原建材城客户总账链接兼容新工作区。收费起算、减免、水电单价和管理费等未确认规则仍待核，不因资产状态自动创建应收。

USD/CNY 保持原币，不自动折算 XOF。客户级退款与错误收款冲正沿用既有原子 RPC、审计、请求号和结果未知锁；退款登记不是银行转账。原币合同收款、旧流水和凭证入口继续保留。

## 验收与发布

正文必须遵循全站路由隔离约定：`[data-app-main]` 的直接正文容器带 `data-route-root` 与 `data-current-route-root`。缺少标记时，全局样式会隐藏已返回的内容。回归需组合真实外壳与全局 CSS 检查计算可见性；响应中存在正文文本、或手工还原 React 流式 HTML，不等于浏览器中可见。

1. 权限、查询范围、对象归属、空态、分页和上下文返回的单元测试；旧财务组件回归。
2. `npm run validate`、`npm test`、`npm run test:operator-concurrency`，后者在隔离本地 PostgreSQL 中验证，不访问线上业务记录。
3. 当前账号只读联调：主页 → 客户 → 客户账户 → 关联资产 → 园区合同 → 安全返回；法文、折叠导航、窄屏、刷新、错误对象验证。不得为验收创建虚假收款。
4. 只读业务表摘要前后对照，再核对本次准确 Git 提交的 CI、Vercel 生产状态和线上已登录页面。管理员技术代测不等于员工本人流程验收。

发布时将具体测试、提交和部署证据记录在独立发布说明；本文件不以历史发布结果替代本次结果。

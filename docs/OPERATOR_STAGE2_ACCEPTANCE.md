## 本轮发现并修复

1. 登录限流跳转位于 `try/catch` 内，被 Next.js 异常式跳转机制吞掉。现移到异常兜底外，并覆盖 email/IP 上限及 RPC 不可用回归。
2. 线上 `property_fee_rules` 不在历史仓库建表迁移中，且允许任意已登录用户修改。已纳入基线；本地迁移按现有 `finance:write` 限制 admin/finance 写入、admin 删除，叠加项目房间访问限制。原线上策略**尚未修复**，随下次授权发布处理。
3. Node 24 加载 TypeScript 样式配置时 `require` 不可用，导致开发页崩溃；改为模块导入并完成网页与构建复测。
4. Next 开发代理把内部主机名规范成 localhost，造成浏览器 127.0.0.1 来源校验误拒绝。新增服务端精确来源配置；仍拒绝其他来源、Bearer 确认和任意 forwarded-host，不放宽 CSRF。
5. Windows PowerShell 默认脚本限制阻断会话加密辅助脚本；改为 .NET DPAPI 辅助程序，不修改执行策略，不明文存令牌。
6. 临时源码快照被根目录 Vitest/TypeScript 递归收集。测试限定到 `src/`、`tests/`，类型检查排除 `work/`；本文使用去重后的数量。

## 可复现入口

```powershell
node scripts/setup-local-full-schema.mjs
# 仅在已验证隔离环境，且业务表/Auth 为空时执行：
node scripts/setup-local-full-schema.mjs --apply
node scripts/check-local-full-schema.mjs
node scripts/check-local-payment-flow.mjs
node scripts/start-local-operator-web.mjs
# 另一个终端构建独立本地包，复制命令输出的路径：
node scripts/package-local-operator.mjs
node scripts/check-local-payment-browser.mjs <本地包路径>
# 按脚本输出的一次性本地账号/链接做浏览器验收，最后输入 VERIFY。
# 仅测 HTTP/连接器、不执行浏览器付款时加 --prepare-only。
```

完整初始化会**事务性替换固定隔离库中已确认无业务数据的应用结构**，先保留 schema-only 备份。它不是线上迁移命令，也不是一般备份还原工具；有任何业务行或 Auth 用户时拒绝执行。本地残留登录遥测也可能触发拒绝，应先核查来源，不直接清空整库。

基线 SHA-256：`6816fa8930d606dcd9c4ac66f5370967ad5a5da60b716165594768627c795dff`。范围是应用 public/private schema，不宣称复制 Supabase 平台内部 Auth/Storage 配置、存储对象、定时任务或所有扩展设置；这些不在本阶段单笔外部截图流程中。导出工具对当前结构进行了对照验证，不是通用 `pg_dump` 替代品。

# 外部录入审计：业务可读阶段

## 交付范围

2026-09-15，本地实现。未提交/推送 Git、未发布 Vercel、未应用数据库迁移、未改写真实业务或历史审计；不新增权限、不增加逐笔复核工作。

现有中法文审计页面复用同一查看组件。新增：

- 按实际录入账号、记录渠道筛选；组合原有日期、动作和模块筛选。
- 搜索请求编号、经办人、录入账号、收据号和原始指令。
- 日租补缴显示本次金额；详情显示累计已收的历史前后值、日期、收据号、输入来源、连接器/协议版本。
- 详情紧邻对应表格行展开；原始变更字段默认收起，前后数据与元数据分别展示。
- CSV 导出当前筛选结果，新增账号 ID、经办人、渠道、请求编号和原始指令；所有导出单元格对公式起始字符作文本处理。
- 时间按 Africa/Abidjan 展示，避免员工设备时区与业务日期不一致。

## 证据边界

- 实际录入账号取审计顶层 actor_email / actor_id，不用原始指令或 metadata 中自称的姓名覆盖。
- booking_agent_id 是业务经办人，不是实际收款人；没有原始收款人证据就不能推断。
- 经办人目录查询分批读取。补查名称单独标记为“当前名称”，不修改历史 metadata，不假装是当时姓名；读取失败仍显示记录 ID。
- 渠道来自历史记录的 channel，仅标为记录值；空缺/未知值不推断为网页，也不构成身份认证证据。
- 本阶段只对明确的日租 supplementary_payment 记录解释收款金额；异常金额不转换成零。其他动作仍保留原始字段，不套用日租规则。
- 审计记录的存在不等同于人工复核通过，也不证明当前账务已再次复查。共享账号形成的旧记录无法补出实际人员身份。
- 界面保持只读，原有页面角色和 RLS 不变。没有给黄姐创建/授权账号，也没有增加复核按钮。

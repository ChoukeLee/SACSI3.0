# 剩余财务写入入口收拢

日期：2026-09-24。范围为工程化后续第 1 项；不等同于全部历史技术债清零。

## 事务边界

| 入口 | 数据库中的同一事务 |
|---|---|
| 手工记账 | 流水、可选收款、关联关系、审计、防重记录 |
| 出售收款 | 合同锁、分期、应收、收款、流水、审计、防重记录 |
| 灵活分期 | 分期、唯一可匹配应收、合同版本、审计 |
| 出售过户、终止 | 合同状态、相关未结清应收/分期、必要房态、审计 |
| 日租历史补录 | 已退房订单、应收、可选实收与流水、审计；不改变当前房态 |
| 日租财务同步、撤销误入住 | 订单/房态变更、统一财务计算、审计 |

页面继续调用 Server Actions；普通登录客户端调用认证 RPC。服务器不再以管理员密钥执行手工记账，不再逐表拼接上述事务。删除无人调用的旧应收写入文件和旧日租/出售财务写入实现，避免后来误用。

数据库入口为 public.finance_operation_rpc，公开函数使用 invoker，受控实现置于 private、固定空 search_path；内部旧出售过账核心取消客户端执行权限。角色和项目权限在重放查询之前检查。内部请求表开启 RLS、取消客户端表权限，无客户端 policy 是有意设计。

## 保持与限制

- 手工入账仍按原规则：有外部收据号的收入/押金收入才额外生成收款；没有收据号不自动冲抵任何应收。外币保留原币与历史汇率，流水以 XOF 汇总。
- 终止出售合同不删除真实收款，也不把已经付清的应收改成取消；实际退款必须走退款流程。
- 出售分期的历史应收仍通过日期、类别、金额匹配。不能唯一匹配时拒绝，不猜测；本次未批量改造历史外键。
- 日租补录维持既有经办人客户名单，并在数据库重复校验黑名单与房间业务资格。它不是普通新预订。
- 财务修复发现多个应收或非 XOF 历史日租收款时要求人工核对，不猜汇率。
- 变更状态的出售入口和撤销误入住带 updated_at 乐观锁。出售付款先锁合同，再锁分期，减少与终止并发的交错。
- 前端手工记账、出售收款/分期/过户/终止、日租补录只在 sessionStorage 保存操作号和输入摘要，不保存财务表单。明确拒绝或成功后清理；断网或未知结果保留原号、禁止改内容后冒充原请求。
- 管理员日租同步属于重算，不产生新收款；其修复入口生成新的服务端操作号，不宣称具备上述浏览器恢复功能。

## 验证与上线顺序

新增原生 PostgreSQL 测试涵盖真实事务、故障注入回滚、并发重复提交、身份/内容冲突、版本冲突、越权拒绝、历史补录不改房态、保留已收款。浏览器请求身份有独立测试；工程边界测试禁止已收拢入口重新出现直接多表写入。

1. 本地 lint、格式、类型、业务规则、全部单元/原生数据库测试与生产构建通过。
2. 对生产做新加密备份与只读结构/权限预检；仅应用 20260924083457_atomic_remaining_finance.sql，不重放全部历史迁移。
3. 核验新增函数 ACL、业务表未因迁移改变、生产 advisors；推送 main，核验 CI、Vercel 实际提交和普通账号只读页面/连接器。
4. 不用真实收款测试线上写入。颖与黄姐后续真实使用验收应单独记录。

本次未更改连接器协议或安装包。旧 record_sale_payment_rpc 参数接口保留兼容；曾在旧版本完成但结果未知的出售请求可能返回 requestIdConflict，需要核查已有账目，不应换新号再录一次。

仍需后续治理：大型页面控制器、传统入口与 AI 动作目录的进一步统一、历史数据库安全告警、真实人员验收。没有批量撤销所有业务表写权限，也没有修改历史账目。

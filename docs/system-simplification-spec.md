# SACSI 系统精简与重构规格

状态：业务范围已与用户逐项确认，进入分阶段实施。
基准日期：2026-07-29。
原则：准确性优先；先提交数据库，再更新界面；不以“保存中/已保存”掩盖异步或部分成功。

## 1. 产品定位

SACSI 不再定位为覆盖全部房地产、会计、合同、文档和办公流程的综合平台。日常产品范围收敛为：

1. 首页工作台；
2. 日租；
3. 长租；
4. 出售；
5. 房源；
6. 仅管理员可见的系统维护。

财务能力定位为业务收款与资金往来台账，不承担工资、水电采购、维修等完整运营会计。

## 2. 主导航与角色入口

### 2.1 中文管理员

主导航只保留：

- 首页；
- 日租；
- 长租；
- 出售；
- 房源。

账号权限、房源基础维护、数据质量和审计记录统一放入右上角“系统维护”。

### 2.2 法语日租操作员

登录后直接进入法语日租，不进入管理首页。仅提供：

- 日租全部日常操作；
- 日租占用总览；
- 长租只读；
- 账号与退出。

不提供出售、财务、房源维护和系统维护。每名员工使用独立账号，不再多人共享账号。

### 2.3 权限模板

- 管理员：中文，全部核心业务和维护权限；
- 日租操作员：法语，日租操作 + 长租只读；
- 只读：按授权查看，不执行资金或状态变更。

未实际启用的 boss、finance、rental_sales 等前端角色入口不再保留。

## 3. 核心页面

### 3.1 首页

从上至下为：

1. 快捷操作：新建日租、登记长租收款、登记售房收款、日租占用总览；
2. 今日运营：入住、离店、待清洁、当前占用、可入住；
3. 待处理：日租欠款、长租待收、出售待回款、真实数据异常；
4. 本月收款概览：应收、实收、未收、逾期和回款率；
5. 可展开的房态快速查看。

完整房态进入“房源”。首页与房源页必须复用同一份房态数据和卡片组件。

### 3.2 日租

- 日历为默认主界面；
- 顶部只保留日期、新建订单和占用总览；
- 订单操作统一在侧栏完成；
- 保留独立占用总览、复制群消息和打印；
- 不设订单审核；
- 不展示“保存中/已保存”；
- 数据库完整提交成功后才更新界面；
- 历史订单列表为日历辅助视图，不进入主导航。

日租登记字段拆分为：

- 经办人：Chouke、Niamke、悦凯等；
- 创建账号：系统自动记录；
- 住客/联系线索：选填；
- 备注：选填。

历史迁移：

- Chouke、Niamke、悦凯归为经办人；
- 镇淮、镇淮（楠）、镇淮（佳龙）保留为真实租客/联系线索；
- 其他无法确认的历史名称保留原值并标记未分类，不推断。

日租规则：

- 未收款订单可直接取消，不强制取消原因；
- 已收款订单取消前必须处理全退、部分退或保留款项；
- 允许欠款退房，欠款留在原订单继续追收；
- 收款默认不得超过未收金额；
- 续住先修改订单日期和总额，再收款；
- 开放式入住按实际天数、单价和折扣确认最终金额；
- 订单、付款、总账、房态和审计必须原子提交。

### 3.3 长租

默认使用紧凑台账，每行显示：

- 楼栋和房号；
- 租客；
- 月租；
- 月物业费；
- 押金；
- 租期；
- 租金已缴至；
- 当前余额。

详情侧栏显示收款、退款、押金扣除、中介费和房东款。常用操作只有登记收款；其他资金记录收进次级入口。

删除复杂正式退租结算。结束租赁只记录结束日期、释放房间和备注；实际退款、扣款分别按真实资金流水登记。

租金与物业费规则：

- 每份租赁记录保存固定月租和固定月物业费；
- 一笔到账可分配到租金、物业费、押金和中介费；
- 分项合计必须等于最终 FCFA 入账总额；
- 通常共用同一覆盖期间，特殊情况才分别调整；
- 系统根据上次已缴至和月数建议新覆盖期，用户确认后保存；
- 没有明确资料时不反推物业费或未来应收。

### 3.4 出售

默认使用销售台账，每行显示：

- 楼栋和房号；
- 买家；
- 成交总价；
- 累计到账；
- 累计退款；
- 净收款；
- 剩余未收。

详情侧栏显示房款、退款、中介费、车位款和其他真实资金记录。有明确分期计划才显示到期和逾期。

删除过户、产权证、交付、中介档案、佣金状态、合同打印和附件管理。保留简单“撤销出售”，仅管理员可用；已有收款时必须先处理资金。

### 3.5 房源

- 按楼栋、房态、房源类型和楼层筛选；
- 按楼层展示并排房间卡片；
- “5#前楼”等不再单独占一行标题；
- 房间详情只显示基础资料、当前业务、最近收款、业务历史和状态历史；
- 日租资格、默认日租价、用途和启停由管理员维护；
- 已有业务或财务记录的房间只能停用，不能删除。

公寓和办公室为当前常用类型。商铺、车位、仓库等资料不清晰的历史资产保留底层数据，但不进入常用筛选；下一次相关收款时再提示补全。

## 4. 财务口径

### 4.1 统一结算币种

所有财务汇总以 FCFA/XOF 为唯一结算口径。

长租和出售支持原收：

- FCFA；
- CNY；
- USD；
- EUR。

外币收款必须保存：

- 原币币种；
- 原币金额；
- 当时确认的入账汇率；
- 最终 FCFA 入账金额。

历史金额不使用当前汇率重算。原币金额未知时保留 FCFA 主金额，并明确原币金额未知，不反推。

### 4.2 收款方式

默认方式为现金。可选：

- 银行转账；
- 支票；
- 外币兑换/汇款；
- Orange Money；
- Wave；
- MTN Money；
- 其他。

交易流水号或凭证说明选填。不建设移动钱包或复杂银行对账模块。

### 4.3 首页财务卡片

四张卡片统一为：

- 本月应收；
- 本月实收；
- 本月未收；
- 本月逾期。

卡片、回款率和明细侧栏必须使用同一个数据库汇总结果。明细固定显示日期、楼栋+房号、客户/联系人、业务类型、应收、已收、未收和本地化状态。

退款保留原收款和退款流水，并进入净收款计算。逾期只来自明确到期日。

### 4.4 其他真实资金类型

以下能力保留在对应业务详情，不设置独立中心：

- 长租与出售退款；
- 押金退还和押金扣除；
- 中介费收入和支出；
- 物业费；
- 家具费；
- 车位款；
- 房东款；
- 代付款和有明确业务依据的其他资金记录。

代管房源只记录明确的代管标记、可选房东名称、实际收租和实际支付房东款。不计算理论应付房东金额。

## 5. 房态、清洁和暂停使用

- 保留当前待清洁/已清洁状态；
- 不提供清洁历史查询、统计或绩效；
- 历史清洁记录作为审计数据保留；
- 删除维修工单、维修人员、维修费用和维修进度；
- 房间只允许设置“暂停使用”、原因和可选预计恢复日；
- 恢复使用必须人工确认；
- 已有冲突订单时禁止直接暂停或恢复。

## 6. 删除、隐藏与保留矩阵

### 6.1 直接删除页面、入口、API 和业务流程

- 独立助手及操作 API；
- 报表中心与 CSV 报表套件；
- 独立文档/打印中心，日租占用总览打印除外；
- 通知铃铛和通知中心；
- 经营目标页面及 API；
- 导入导出中心及批量导入流程；
- 批量操作中心；
- 黑名单管理和阻断规则；
- 订单审核；
- 正式退租结算界面和流程；
- 维修管理；
- OCR 收据扫描、附件匹配和纸质档案；
- 普通手工应收和普通财务调整；
- 独立前台工作台；
- 独立待办页面；
- 通用设置中心；
- 前端安全备份页面。

### 6.2 删除主导航，但保留上下文能力

- 财务流水：进入首页卡片或业务详情；
- 客户资料：从长租、出售或搜索进入；
- 数据质量：系统维护；
- 审计日志：系统维护；
- 房源基础维护：系统维护；
- 全局搜索：缩成辅助按钮。

### 6.3 必须保留的数据

- 所有历史日租、长租和出售记录；
- 所有应收、收款、退款、扣款、总账和审计；
- 中介、物业、家具、车位、房东款；
- 外币原始信息；
- 客户及历史联系信息；
- 清洁历史；
- 不清晰资产的原始资料。

### 6.4 数据库结构清理条件

表或字段只有同时满足以下条件才可物理删除：

1. 生产数据为零或已安全迁移；
2. 页面、API、服务端函数、RLS、触发器和报表无依赖；
3. 已有可恢复备份；
4. 迁移在本地或隔离环境通过；
5. 应用构建、核心路由和数据核对通过。

`notifications`、`business_targets`、`lease_settlements` 当前生产记录均为零，可列入依赖审计后的候选删除项。历史财务表和类型永不因页面删除而删除。

## 8. 已发现的高风险异常

### 8.1 日租 11# 1105

- 开放式入住：2026-04-24；
- 退房操作：2026-05-26；
- 订单最终金额仍为 40,000 FCFA；
- 关联付款合计 2,440,000 FCFA。

开放订单退房金额计算和已有付款抵扣存在错误。修复前不得自动改写历史金额，需专项核对。

### 8.2 日租 11# 902

- 订单金额 280,000 FCFA；
- 两笔付款各 280,000 FCFA；
- 第二笔 payment 已写入，但没有对应 ledger entry。

这是多步保存部分成功的直接证据。需先确认真实收款，再用审计迁移修复。

### 8.3 当前正式退租代码

代码同时使用界面传入退款额和系统计算退款额，写入总账与结算表时可能不一致；多次 insert/update 也未由单一数据库事务包裹。该流程按已确认范围删除，不继续修补旧交互。

## 9. 实施阶段与审核门

1. 固化规格和删除依赖图；
2. 修复日租原子性、金额校验和两笔异常；
3. 收敛导航、角色和系统维护；
4. 重构首页与统一收款概览；
5. 重构日租；
6. 重构长租；
7. 重构出售；
8. 重构房源；
9. 删除已确认低频模块；
10. 全量回归、权限与数据审计。

每阶段必须完成：

- 变更前生产数据快照；
- 数据库迁移可重复执行或具备明确幂等保护；
- 类型检查和测试；
- 生产构建；
- 中法文权限路由检查；
- 核心金额对账；
- 阶段性审核结论；
- 审核通过后才推送下一阶段。

## 1. 产品定位

SACSI 网页继续负责业务页面、人工操作与审计查看。外部 Codex 是本地自然语言操作入口，不再继续把内嵌 AI 对话页作为主要工作方式。

员工电脑不需要维护完整开发仓库，不保存 `SUPABASE_SERVICE_ROLE_KEY`，也不能使用任意 SQL 作为业务操作方式。外部工具只能调用登记过的 SACSI 业务动作。

## 2. 人员和身份

- 小颖是主要录入人，覆盖日租、长租和出售。
- 黄姐是日租共同负责人，也拥有三类业务的完整录入能力。
- 两人分别使用自己的 OpenAI/Codex 账号和 SACSI 账号。
- OpenAI 账号负责 Codex 使用身份；SACSI 登录身份是业务授权与审计归属的唯一依据。
- 黄姐可查看全部审计日志，不增加逐笔“已复核”流程。

外部连接器首次使用时登录 SACSI，之后安全复用短期访问令牌和轮换刷新令牌。连接器向操作接口发送 Bearer 访问令牌，服务端通过 Supabase Auth `getUser(token)` 验证真实用户；网页仍可使用原有 Cookie 会话。每次请求都重新建立用户上下文，不能相信客户端提交的操作人姓名或 ID，也不能把令牌写入日志或协助报告。

业务动作权限采用两层来源：原有网页角色权限继续有效；确有职责需要时，可由系统维护者向具体 SACSI 账号授予额外业务动作。额外授权不改变网页角色，也不会授予代码、数据库、账号或系统设置权限。授权目录和记录保存在 `private` schema，员工端不能直接读取或修改表。

## 3. 执行策略

确认策略由 `operator-execution-policy.ts` 统一决定，授权仍由业务动作注册表、登录身份和数据库策略共同决定。

| 场景 | 处理方式 |
| --- | --- |
| 查询 | 直接执行 |
| 自然语言发起的 L1/L2 常规业务动作 | 直接执行并复查 |
| L3 冲销、历史纠正、解除合同等高风险动作 | 展示影响后二次确认 |
| Excel 截图识别出的写操作 | 展示结构化清单后确认 |
| 批量写入 | 展示整批清单后确认 |
| 已知动作下的特殊业务情况 | 标明例外原因后二次确认 |
| 未登记动作、任意 SQL、代码/结构/权限修改 | 阻止执行并生成协助报告 |

“直接执行”不等于绕过保护。所有写操作仍必须具备幂等请求号、执行前版本校验、业务冲突检查、原子 RPC（适用时）和执行后数据库复查。

## 4. 审计证据

每次外部操作应记录：

- SACSI 实际登录账号和显示名；
- 业务经办人（与实际录入人分开）；
- 原始自然语言或截图识别文字；
- 结构化动作、目标和计算依据；
- 操作前快照、预期影响和操作后结果；
- 请求编号、连接器版本、服务端版本；
- 是否属于截图、批量、例外或高风险操作；
- 成功、失败、冲突及执行后复查结果。

审计页面使用业务语言展示，不允许操作人修改或删除原始日志。

本地已补齐业务可读审计：按实际账号/记录渠道筛选，搜索请求号和原始指令，展开查看经办人、本次收款、累计已收前后值及协议证据，并导出当前筛选结果。目录补查的经办人名称注明“当前名称”；旧记录缺少账号、渠道或收款人时不猜测补齐。没有增加逐笔复核按钮，详见 [审计阶段验收](OPERATOR_AUDIT_ACCEPTANCE.md)。

## 5. Excel 截图和组合收款

流程固定为：截图识别 → 结构化清单 → 查询合同与应收 → 生成分账建议 → 人工确认 → 分项入账 → 逐项复查。

例如，4# 公寓 408 的六个月租金及物业费合计 384 万 XOF；月租金 60 万、月物业费 4 万时，建议拆分为租金 360 万、物业费 24 万。总额、期间或既有计费数据无法平衡时暂停冲突项，不自行制定财务规则。

原始截图不保存到 SACSI。审计只保存识别文字、引用的数据、计算过程、确认后的清单和执行结果。现有财务 Excel 保持独立，短期不开发自动对账。

## 6. 版本和离线边界

- 开发在本地工作区进行；每轮本地核验，阶段性提交和发布。
- 员工端只使用经过验证的稳定连接器版本。
- 连接器发现协议或服务端版本不兼容时停止写入并生成问题报告。
- 离线阶段只保存加密的待同步业务单；恢复联网后必须重新查询、查重和校验，不能把离线草稿显示为已入账。

## 7. 实施顺序

1. 固化执行/确认/阻止策略及回归测试。
2. 设计带版本号的外部连接器协议和 SACSI 登录会话。协议清单位于 `GET /api/operator/v1/capabilities`，仅对已登录用户返回当前账号的有效能力，且不包含任何密钥。

## 8. 当前本地接口

`GET /api/operator/v1/capabilities` 返回当前 SACSI 登录账号的协议版本、身份与有效动作权限。

`POST /api/operator/v1/actions` 当前只实现两项：

- `query_daily_booking`：按 `bookingId`，或按 `buildingCode` + `unitNo` 查询。房间存在多个候选订单时只返回候选清单，不猜测历史订单。
- `record_daily_payment`：只接受正整数 XOF、明确日期、订单 ID 和 UUID 请求号；沿用原子收款 RPC，写后复查付款、订单、应收和当前操作人的审计记录。

请求必须携带协议版本、连接器版本、原始指令、输入来源和请求号。自然语言常规收款可直接执行；Excel 截图、批量或例外情况只返回 `confirmation_required`，当前阶段不会因为客户端重复提交或自行附加“已确认”字段而绕过确认。确认凭证机制会在截图/批量链路阶段单独实现。

本地截图准备入口 `POST /api/operator/v1/confirmations/prepare`：单笔固定日期日租收款可生成绑定账号、请求、快照、版本及期限的预览凭证。**预览不代表已确认，也不能用来执行收款**。已实现待确认单、同账号确认页面及事务内付款，默认关闭且未发布。失效/修改单可在重新预览后向 drafts 传 `replacesConfirmationId`，保留原请求号、使旧单失效并生成新单，不能把已执行付款重新准备。详见 [确认进展](OPERATOR_CONFIRMATION_PROGRESS.md) 和 [五阶段交付审核](OPERATOR_FIVE_STAGE_DELIVERY.md)。

日租收款审计由数据库根据 Supabase 登录身份写入实际操作人，并保存连接器/协议版本、输入来源、原始指令、请求号以及收款前后财务摘要。客户端提交的操作人姓名或 ID 不参与审计归属。

## 9. 联调记录与未验收项

### 本地收款证据校验补强

收款接口现在会逐项比对持久化付款与请求中的订单、请求号、金额、日期、收据号和币种，并核对审计实际操作人及当前订单/应收金额。证据缺失或不一致时返回 `verification_failed` 和不含业务原文的原因代码，明确 `recheck_same_request_id_only`，禁止通过换请求号自动重录。

旧远程 RPC 对同请求号不同金额/日期仍可能返回旧结果。本地新增 `20260915150854_harden_operator_daily_payment_integrity.sql`，补齐锁内业务字段和原操作人比对、事务内财务/流水/审计核验及失败回滚。该迁移**尚未应用远程**。

本地接口写入前要求数据库 `operator_daily_payment_protocol_version()` 返回 `2`；缺少新迁移时返回 `database_upgrade_required`，不会先写入再报版本错误。已发出写入后发生网络错误时返回 `execution_unknown`，不能解释为未入账；保留原请求号核实，禁止新请求号重录。

现有测试分三层：证据校验单元测试、HTTP 处理函数的故障模拟、PGlite 内存 PostgreSQL 上实际迁移 SQL 与 HTTP→SQL 集成测试。虚构订单不来自生产库，测试不加载 `.env.local`，也不创建磁盘数据库。测试包括提交后响应丢失、原请求号重试、字段冲突、归属错误和触发器异常回滚。运行 `npm run test:operator-payment`，详见 [收款验收记录](OPERATOR_PAYMENT_ACCEPTANCE.md)。

- 远程迁移版本：`20260914133925_add_operator_action_grants`、`20260914133928_add_external_operator_daily_actions`；本地文件名与远程记录对齐。
- 普通管理员通过 Supabase Auth 登录，使用用户令牌（非 Service Role）获得 33 项权限目录；目录数量不代表全部动作已实现。
- 本地应用连接远程数据库：权限接口返回 HTTP 200；无会话返回 401；日租查询返回 200 和 `selection_required`，未唯一确定订单时要求选择，不代表已经验证单一订单快照。
- 不兼容协议返回 HTTP 409；Excel 截图收款请求返回 HTTP 202 / `confirmation_required`，未执行收款。
- 未创建、修改或删除真实订单和财务记录。当前已验证内存数据库交易逻辑及原生 PostgreSQL 的 12 项多连接并发场景；完整 Supabase 部署中的 Auth/RLS/触发器组合仍待验收，不能把精简测试夹具视为生产镜像。并发套件单独运行 `npm run test:operator-concurrency`。
- 截图确认凭证、员工端连接器、长租/出售操作和离线队列仍未交付。后续先补齐收款冲突保护与隔离测试，再进入员工端试用；本轮不推送 Git 或 Vercel。

# 五个工作台的详情与办理流程收尾 · 2026-10-20

## 范围与不变项

本轮只调整长租、出售、财务、客户和资产的详情与办理界面。日租入口、原房态日历和日租收款分析不改；不执行数据库迁移，不调整角色权限，不创建线上业务记录。

既有服务端操作、金额口径、请求幂等、记录版本核验、原币显示和审计路径继续复用，不通过 UI 重做改写账务规则。

## 收尾后的路径

| 模块 | 唯一详情入口 | 直接办理 | 保留内容 |
| --- | --- | --- | --- |
| 长租 | 列表、楼层与指标均选中同一合同 Inspector | 实际收款继续进入专用收款工作台；押金/其他账务、启用、退租和管理员账期纠正由详情直接发起 | 完整合同条款、原币、纳管应收、经营现金、押金实收实退、全部付款记录、打印 |
| 出售 | 列表、楼层与指标均选中同一履约 Inspector | 登记收款、增加分期、更新过户和终止分别使用单一用途表单 | 完整计划/核销状态、全部付款历史、原币、过户资料、中介与佣金约定、打印 |
| 财务 | 保留新财务工作台和原核对入口 | 手工记账只有一个抽屉、一份表单和一个楼栋上下文 | 仅非业务收支、授权范围按需读取、四类收支方向、失败保留、原请求幂等 |
| 客户 | 目录侧栏看概况；独立档案展开收款/单据/完整历史 | 有权角色直接复用客户编辑表单 | 业务关系、住客/经办人区分、原币财务、附件与单据、打印、审计、全部分页历史 |
| 资产 | 目录 Inspector 看状态/业务关联/状态历史；独立档案看全量历史 | 修改运行条件只打开专用运行条件表单，不再套第二套档案 | 权属、占用、运行条件独立显示，原版本核验、建设核验提示、全部业务和财务历史 |

“独立完整档案”是可复制地址、可跨业务定位的历史页面，不再是办理前必须穿过的第二层摘要。客户与资产档案采用工作台标题、轻量导航和统一的资料/历史层级。

## 必须核验的边界

- 选择/项目/楼栋/分页切换不能沿用旧对象的办理上下文；旧的异步读取和提交回包不得打开/关闭另一个对象的表单。
- 未成功读取详情不显示旧余额、不允许办理；按钮权限和原服务端权限同时保留。
- 合同预计结束不等于实际离开；登记覆盖日不推定欠款；合同佣金/押金标记不推定实际现金。
- 押金与经营收入分开，应收核销与付款事实分开，原币与 XOF 折算分开。
- 所有历史保留分页或完整滚动，不继续用六条付款截断冒充完整记录。
- 关闭办理表单回到同一对象的详情；安全 returnTo 与精确合同/资产链接保留；中法语与窄屏可访问。

## 验证与发布

执行 `npm test`、`npm run validate` 和独立回环库 `npm run test:operator-concurrency`。浏览器使用既有授权账号打开真实数据与办理表单，不提交真实收款/退租/终止等业务操作。自动回归覆盖提交参数、失败与并发边界，不能冒充员工实际操作验收。

发布沿用 main 的 Git 自动部署。最终须核对同一提交 SHA 的 CI、Vercel 提交状态和 Production deployment 成功，再检查公开生产地址。推送成功本身不代表上线成功。若管理连接缺少团队授权，不更改账号权限或新建项目；明确记录聚合运行日志的可见性缺口。

截图与具体构建/部署证据保存在本地忽略目录 `work/workbench-flow-finish-20261020/`，不提交真实客户截图或认证状态。最终运行结果以本轮交付说明为准。

## 最终本地技术结果

- `npm run validate`：ESLint、444 个治理文件的格式检查、日租规则守卫、TypeScript 与 Next.js 生产构建通过。
- `npm test`：247 个文件、3,148 项通过；1 个条件性测试文件/用例跳过，不能表述为零跳过。
- `npm run test:operator-concurrency`：30 个独立原生 PostgreSQL 文件、453 项通过，1 项需显式启用顾问检查的条件跳过。
- 独立复核后修复了长租同范围切换目标的延迟响应、排除现金记录的错误正号，以及资产旧请求关闭新目标表单的问题，并加入有效目标的回归。
- 真实授权数据的本地生产构建检查涵盖五个工作台的详情/专用表单，全部取消或只读，不提交业务写入。客户与资产档案检查 390px 与法语 320px 窄屏；表格仅局部横向滚动，实测没有拉宽整页。
- Vercel 管理连接本轮仍返回目标团队 `403`，本地没有已安装的 Vercel CLI；沿用既有 Git 集成发布并以相同 SHA 的提交/部署状态及生产页面复查为准。平台聚合运行日志不可读取，不声称已完成全量线上日志扫描。

# 产品方向决策记录

> 状态：已确认（2026-08-14）
> 决策人：科建地产（业主）

## 决策

**采用「单租户产品化」路线（路线 A）。**

- 一套代码，每个客户（地产公司）独立部署一套实例（独立 Supabase 项目 + 独立数据库 + 独立域名）。
- 不建设多租户 SaaS（一套实例多公司共享）。
- 暂不为未来多租户预留 `tenant_id`（避免提前复杂度；若未来确需，再按专项改造）。

## 决策依据

1. 当前系统深度绑定科建一家业务：楼栋编号（SACSI3/4/5/6/7/11）、日租默认价（40,000 XOF）、角色岗位均写死。
2. 尚无第二家付费客户或明确的跨公司共享需求。
3. 单租户改动小、见效快，可在 3–6 个月内把系统打磨到可稳定交付。

## 对路线图的影响

- ✅ 继续：阶段 2（修复 1105 / 902 两笔错账）、阶段 3（报表/导出、提醒/通知、多币种展示、角色收敛、双语补齐）。
- ❌ 不做：阶段 4（多租户 tenant_id、订阅计费、租户 onboarding、白标）。
- 若未来出现多家客户：先以「新部署一套实例」的方式交付，积累多实例运维经验后再评估是否重做多租户。

## 交付形态

- 每交付一个新客户：新建 Supabase 项目 → 跑迁移 + 种子数据 → 部署 Vercel 实例 → 配置楼栋/价格/角色。
- 需要补充「新客户初始化」文档与脚本（后续阶段 3 追加），使部署可重复、可自动化。

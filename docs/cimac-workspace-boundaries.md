# CIMAC 独立工作区

## 业务入口

- 首页 `/cimac`，商铺分布 `/cimac/map`。
- 客户 `/cimac/customers`，客户详情含总账、收费约定、抄表及资料。
- 资产 `/cimac/assets`，资料、运行条件及关联业务留在园区工作区。
- 合同 `/cimac/contracts`，原币收款 `/cimac/contracts/[id]/collect`。
- 资金 `/cimac/finance`，流水 `?kind=ledger`，应收 `?kind=receivables`。
- 分析 `/cimac/reports`；历史出售只读 `/cimac/contracts/history/sales/[id]`。
- 以上均有 `/fr` 法语入口。

SACSI 普通工作区不再列入 CIMAC 项目业务。明确指向园区项目、资产、合同的旧地址按当前会话可见的数据库归属跳转；冲突参数不猜测、不回落全部。

## 共享与独立的边界

同一数据库、同一不可变记录 ID；客户身份共享，合同、资产、财务关系分项目展示。共享登录、RLS、原子记账、幂等、版本检查、凭证和审计底座，CIMAC 不另建一套收款逻辑。

客户目录可新建共享身份，成功后在园区合同页预选该客户。原有新建表单及权限保持不变；仅新建共享身份不会自动建约或收费。管理员还可以显式建立园区客户名册与铺位资料关联，不再要求先虚构一份租约。

### 园区名册与资料关联

- `cimac_customer_directory_read_rpc` 只读当前 CIMAC 授权范围，默认显示当前名册，归档列表及历史详情另行查看；无合同、无关联资产的园区客户资料也可保留。
- 同一公司可以复用现有共享客户 ID，分别关联不同项目、品牌和铺位；不根据同名、相同电话或备注自动合并主体。客户跨项目关联须明确选择已有 ID。
- 显式铺位资料使用 `park_link`，不是租赁/销售合同。已有真实业务关系按客户和铺位去重，并补充品牌、资料来源及签署确认；不得为资料链接生成合同业务路由。
- “合同资料已确认生效”与已起租、已交付、已收款分开。签署日期未知留空，原租约状态和历史账务不随资料确认自动改变。
- 管理员通过 `cimac_customer_profiles_sync_rpc` 原子维护名册及资料链接。调用必须携带固定请求 ID、预期客户版本和来源，真实操作者及前后状态一并审计；同号同输入重试返回原结果，输入冲突或过期版本整批拒绝。
- 归档只隐藏 CIMAC 当前名册，保留共享身份、原合同、收退款、流水及其他项目业务；仍有当前园区业务的客户不能归档。恢复名册不会自动恢复或新建合同。
- 本轮资料链接仅显式新增/更新，不删除历史链接。新增归档、恢复及铺位资料维护入口只向管理员开放，不扩张原有客户角色权限或证件处理范围。
- `cimac_asset_areas_sync_rpc` 是独立的面积元数据更正：同样校验实际管理员、项目边界、固定请求和资产版本，仅更新指定资产面积并审计。不均摊不明确的合计面积，也不自动重算收费规则、已开应收、历史收款或合同。

合同和财务来源的个人信息、同步计划、原件渲染及业务快照保存在本机私有核对目录，不作为代码、迁移种子或测试资料提交。

公司级审计仍在 `/settings/audit-logs`；原有全公司关联核对保留在 `/settings/finance-reconciliation`，两者受原授权角色约束。不得把公司级结果标成园区结果。

不清空、不搬录、不自动换汇。历史收款、分账、退款、冲正和附件保留。未归属记录不擅自算入项目，继续从明确标注范围的共享核查工具核对。未确认收费规则仍为待核，物业工单、交付和开业流程不因导航迁移被视作已建成。

## 验收要求

首屏、后续查询、详情预览、分页、导出、操作准备及刷新保持同一项目边界；客户跨项目、不同表相同 UUID、冲突来源、空授权范围均须回归。账户变更、原币和账务历史不能因 UI 分离改变。

发布前需要类型、lint、格式、构建、单元/数据库回归及真实浏览器只读验收；生产验证不以写入真实测试账单代替。

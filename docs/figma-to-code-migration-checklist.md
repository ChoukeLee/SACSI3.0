# SACSI Figma To Code Migration Checklist

## 目标

这份清单用于 Figma 设计稿通过后，把新 UI 稳定迁移到 SACSI 代码中。迁移必须优先改共享组件，再改页面，不允许按截图在页面里堆一次性样式。

## 迁移总原则

- 业务逻辑不变。
- 数据库结构不变。
- 财务同步不变。
- 审计日志不变。
- 先组件，后页面。
- 先桌面核心路径，后移动端和低频页面。
- 每次只迁移一个页面族。
- 每个页面族迁移后必须构建通过。

## 迁移前准备

### 1. 确认 Figma 设计稿范围

检查：

- 是否包含 desktop 1440px。
- 是否包含至少一个打开的右侧抽屉。
- 是否包含 loading、empty、error 状态。
- 是否包含中文和法语长文案测试。
- 是否包含欠款、逾期、维修、待清洁等风险状态。

通过条件：

- 核心状态没有缺失。
- 组件命名和文档基本一致。

### 2. 截图当前线上页面

需要截图：

- 日租业务页。
- 长租合同页。
- 出售合同页。
- 房源总览页。
- 财务应收页。
- 客户档案页。
- 审计日志页。

通过条件：

- 每个页面都有迁移前截图，用于确认没有漏掉业务信息。

### 3. 标记代码落点

对照表：

| Figma 组件 | 代码落点 |
|---|---|
| Button | `src/components/ui/button.tsx` |
| IconButton | `src/components/ui/button.tsx` 或新增包装组件 |
| Input | `src/components/ui/input.tsx` |
| SearchInput | `src/components/ui/search-input.tsx` |
| DateInput | `src/components/ui/date-input.tsx` |
| SegmentedControl | `src/components/ui/operational.tsx` |
| StatCard | `src/components/ui/operational.tsx` |
| Table | `src/components/ui/business-table.tsx` |
| Drawer | `src/components/ui/sheet.tsx` 或新增 `drawer.tsx` |
| RoomCard | `src/components/room-card.tsx` |
| DailyBookingBar | `src/features/daily-rentals/calendar.tsx` |
| ContractCard | 新增共享合同卡片组件 |

通过条件：

- 没有把共享组件设计直接写进某个页面文件。

## 阶段 1：共享组件迁移

### 1. Button

检查：

- 主按钮、次按钮、幽灵按钮、危险按钮、图标按钮是否齐全。
- loading 状态是否不改变宽度。
- 同一工具栏按钮高度是否一致。

回归页面：

- 日租新建入住。
- 长租新建合同。
- 出售新建合同。
- 财务导出。

### 2. Form Controls

组件：

- Input
- SearchInput
- Select
- DateInput
- Textarea

检查：

- 高度统一。
- focus 状态统一。
- error 状态清楚。
- Textarea 不出现多余拖拽条或悬浮条。

回归页面：

- 日租新建入住抽屉。
- 长租收款抽屉。
- 出售付款抽屉。
- 客户搜索。

### 3. SegmentedControl / FilterBar

检查：

- 激活态统一。
- 楼栋切换不撑满整行。
- 状态筛选支持 count。
- 筛选切换不跳顶。

回归页面：

- 房源总览。
- 客户档案。
- 长租合同。
- 出售合同。
- 财务筛选。

### 4. StatCard

检查：

- 普通展示卡和可点击卡片状态一致。
- selected 状态清楚。
- 数字层级稳定。
- 法语长标题不挤压金额。

回归页面：

- 长租 KPI。
- 出售 KPI。
- 财务 KPI。
- 管理驾驶舱 KPI。

### 5. BusinessTable / FinanceTable

检查：

- 表头高度统一。
- 金额右对齐。
- 备注可截断。
- 横向滚动只在表格内部出现。
- 右侧列不被抽屉裁掉。

回归页面：

- 财务应收。
- 财务流水。
- 欠款明细抽屉。
- 审计日志。

### 6. Drawer

检查：

- 右侧抽屉贴合顶部栏和右边界。
- overlay 不遮挡异常。
- 关闭按钮位置一致。
- 宽表抽屉不把内容推到页面最左。
- sticky header/footer 正常。

回归页面：

- 日租订单详情。
- 当前欠款明细。
- 本月结算明细。
- 长租 KPI 明细。
- 出售 KPI 明细。
- 房间详情。

### 7. RoomCard

检查：

- 空闲、出售、长租、日租、维修、待清洁、自用状态清楚。
- 底部按钮居中。
- 按钮之间间距稳定。
- 长客户名不压住金额和按钮。

回归页面：

- 房源总览。
- 长租合同卡片。
- 出售合同卡片。

## 阶段 2：页面族迁移

### 1. 日租业务页

迁移内容：

- 顶部摘要。
- 操作工具栏。
- 状态筛选。
- 日历布局。
- 订单详情抽屉。
- 新建入住抽屉。
- 欠款/结算抽屉。

业务回归：

- 创建固定离店未付款订单。
- 创建固定离店已付款订单。
- 创建非固定离店未付款订单。
- 创建非固定离店已付款订单。
- 入住。
- 确认预订。
- 续住。
- 收款。
- 退房。
- 标记待清洁。
- 标记维修。

通过条件：

- 点击不跳顶。
- 操作立即有反馈。
- 财务和审计同步。
- 日租只展示 11#公寓。

### 2. 长租合同页

迁移内容：

- 楼栋切换。
- KPI 卡片。
- KPI 明细抽屉。
- 合同卡片。
- 合同详情抽屉。
- 收款、续租、退租操作。

业务回归：

- 楼栋切换后 KPI 同步变化。
- 点击生效合同 KPI。
- 点击 15天内应缴 KPI。
- 点击待收未逾期 KPI。
- 点击逾期金额 KPI。
- 新建合同。
- 收款。
- 退租。

通过条件：

- KPI 明细和卡片数字一致。
- 合同卡片不挤压。
- 15天内应缴、待收未逾期、逾期金额不重复。

### 3. 出售合同页

迁移内容：

- 复用合同页结构。
- 出售 KPI。
- 出售 KPI 明细抽屉。
- 合同卡片。
- 付款计划。
- 过户状态。

业务回归：

- 楼栋切换。
- 点击合同总额。
- 点击已回款。
- 点击待回款。
- 点击逾期回款。
- 点击已过户。
- 记录付款。
- 更新过户状态。

通过条件：

- 没有乱码。
- 出售和长租视觉同源。
- 回款和过户逻辑清楚。

### 4. 房源总览页

迁移内容：

- 资产 KPI。
- 楼栋切换。
- 楼层切换。
- 状态筛选。
- 房源结构图。
- 房间卡片。
- 房间详情抽屉。

业务回归：

- G、0、1、2 楼层顺序。
- 11#日租房状态。
- 5#整层办公室。
- 维修房间。
- 待清洁房间。
- 出售房间。

通过条件：

- 无意义 0 状态隐藏。
- 特殊资产正确展示。
- 房源颜色不混乱。

### 5. 财务页

迁移内容：

- 金额 KPI。
- 收款结构图。
- Tabs。
- 筛选栏。
- 应收表格。
- 流水表格。
- 欠款明细抽屉。
- 收款详情抽屉。

业务回归：

- 日租收款。
- 长租收款。
- 出售收款。
- 部分收款。
- 逾期。
- 导出。
- 备注查看。

通过条件：

- 财务实时读取。
- 表格右侧完整显示。
- 金额不旧账。
- 备注和房号不丢。

## 阶段 3：清理

清理目标：

- 重复按钮样式。
- 重复卡片样式。
- 重复表格壳。
- 重复抽屉布局。
- 乱码文案。
- 直接写死在组件里的中英文混合说明。
- 不再使用的局部 UI helper。

检查命令：

```bash
rg -n "è|Â|Ã|font-black|rounded-2xl|shadow-2xl|style=|className=.*h-\\[|className=.*w-\\[" src
```

说明：

- 这条命令只是扫描风险，不是所有命中都必须删除。
- 对业务状态色和日历尺寸要人工判断。

## 阶段 4：验证

每轮迁移后运行：

```bash
npm run typecheck
npm run build
```

手动验证：

- 页面首次打开。
- 楼栋切换。
- 筛选切换。
- 打开详情抽屉。
- 打开宽表抽屉。
- 创建或更新业务。
- 财务同步。
- 审计日志。

## 推送规则

每个页面族单独提交。

建议提交格式：

- `feat: apply figma system to daily rentals`
- `feat: apply figma system to leases`
- `feat: apply figma system to sales`
- `feat: apply figma system to units`
- `feat: apply figma system to finance`

不要把多个页面族混在一个大提交里，除非只是共享组件基础迁移。

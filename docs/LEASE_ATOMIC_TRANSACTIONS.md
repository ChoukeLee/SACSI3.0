# 长租多步写入事务化

日期：2026-09-23。本轮仅本地实现及合成数据验证，没有读取或修改生产业务记录，没有推送，没有替换员工连接器。

## 完成范围

| 业务入口 | 现在的原子边界 |
|---|---|
| 新建合同 | 合同、自动合同号、房态、租金应收、勾选实收的押金及流水/应收、本人审计、幂等结果 |
| 激活草稿 | 冲突检查、合同版本、应收生成、房态和审计 |
| 管理员终止 | 合同终止、既有应收取消、房态和审计；保留原行政终止语义，不等同退租结算 |
| 退租结算 | 实际补收冲抵现有应收、押金余额核验、实际退款、押金扣除转出/收入、结算单、合同/房态、未来未收租金应收取消和审计 |
| 普通及组合长租收款 | 原币、历史汇率、内部编号、收款、流水、应收抵扣、已缴至日期、下一期应收和审计；不再出现“收款成功但下一期生成失败”的分步提交 |

所有新入口保留实际登录会话。新增 public RPC 为 SECURITY INVOKER，必要的跨角色事务实现放在 private schema 中，显式检查当前登录、角色、房源项目范围；匿名和 service_role 不能调用新长租事务入口。private 幂等记录表无直接客户端读写权限。

建约权限不等于财务权限：rental_sales 可以建约，但不能通过“押金已收”勾选绕过原有长租收款角色边界。此时整笔拒绝，需由有权限的财务账号另行登记。

## 已确认的退租规则

用户已确认本轮修正以下旧账务矛盾：

- “本次补收租金”必须是已实际收到的钱，需勾选确认并明确收款方式；默认 0，不再把界面欠款金额自动填成收款。
- 只冲抵该合同既有到期欠租，不另造一笔“已支付应收”；超过已有欠租的金额拒绝。
- 押金以原币乘各笔历史汇率折算，核对实收减已退/已扣与押金负债流水。缺失、无法归属、付款和流水不一致则停止并提示核对，不能直接按合同约定押金退钱。
- 本次押金退还加扣除必须等于核实的剩余实收押金。扣除为非租金扣款，记录负债转出及收入；不暗中替客户冲抵欠租。
- 未来已收/部分收款的租金应收、待核实/排除的应收不自动取消。特殊情况先人工核对。
- 未补收的既有欠租保留；退租后可继续录入对应欠租的真实收款，但不能超出欠款或生成下一期应收。
- 已售资产退租/终止不会被错误改成“未售可租”，保留 sold 状态。

本轮不重新解释免租、起租、物业费规则；未开业或日期未确认合同不能被自动激活为有应收的合同。纯管理员终止依然保留旧的取消应收语义，实际收退款应使用结算/财务入口。

## 防重与并发

- 客户端在首次发送前保存请求 UUID 和输入 SHA-256，仅存于当前标签页 sessionStorage，不保存表单内容。
- 结果未知时保留原编号；同一请求改金额会被阻止，并显示原操作号。只有明确数据库拒绝（整笔回滚）或成功，才清理本地请求。请求冲突不当作可直接另起请求的失败。
- 服务端绑定请求号、实际账号、操作和完整参数；相同请求重放返回原结果，换账号/换内容拒绝。
- 数据库串行锁和合同版本校验阻止两个生效合同、重复结算和重复收款。失败不会留下已完成请求标记，可用原编号重试。
- sessionStorage 不是跨设备离线队列。未知结果时不能关闭标签页后重开一笔；应保留显示的请求号核对审计。员工连接器的加密待办机制不在本轮修改范围内。

3. 普通账号核对角色、项目范围与只读页面，再按单独授权做最小业务验收，才恢复长租写入。
4. 迁移没有批量改写既有账务。已处理请求、流水、结算和审计必须保留；不能通过删表/删流水回退。发生故障先停相关写入，优先向前修复；回滚旧网页会失去本轮生命周期原子保证，不能当作无风险恢复。

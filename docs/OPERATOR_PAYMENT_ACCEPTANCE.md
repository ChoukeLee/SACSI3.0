# 外部操作：日租收款阶段验收

## 范围与部署状态

本阶段改进日租收款可靠性及入口身份校验，不发布 Git/Vercel、不改真实收款、不扩大员工权限。经办人名单按用户确认统一为“振咏”，其他工作区改动保留。

待发布迁移：`20260915150854_harden_operator_daily_payment_integrity.sql`。迁移由 Supabase CLI 创建，已在本地内存 PostgreSQL 和原生 PostgreSQL 临时测试库运行。远程仍是上一版本，**不能把本地测试通过等同于生产已升级**。

## 已实现的保护

- 公共收款函数保留原签名，改为 `SECURITY INVOKER` 包装；写入实现放在私有 schema，检查权限并设置空 `search_path`。匿名调用被撤销执行权限。
- 未登录身份不能依靠默认角色或 NULL 布尔值通过业务动作检查。
- 同请求号使用事务级 advisory lock。重复请求逐项核对订单、来源、动作类型、金额、日期、规范化收据、币种/汇率和原审计操作人；变化时拒绝，不增补另一笔付款。
- 重试允许传输说明和连接器版本变化，但不会覆盖原始审计。审计缺失或已冲销的旧请求停止并要求核实。
- 收款前要求唯一有效应收且客户、房间、楼栋、币种和业务类别正确；发现已有账务不一致时不自动修账。
- 写入付款、流水、同步应收及订单、插入审计后，在同一事务内核对结果；不一致时整笔回滚。
- 审计保存真实登录人和独立的业务经办人，不接受客户端指定实际操作人；复查历史余额增量，不误用之后的当前余额。
- 应用先检查数据库版本 2，再允许写入；复查要求版本 2 的五项检查全部通过。
- 写入回复丢失时返回“结果未知”，保留原请求号。原请求号重试可恢复已提交结果，不新增付款或审计。

## 可重复本地验证

2026-09-15 收款阶段结果：收款专项 77 项通过（其中 39 项 SQL 交易/权限测试、5 项 HTTP→实际 SQL 集成测试）；日租规则检查、TypeScript 检查和生产构建通过。后续统一经办人名单并新增 9 项入口身份测试后，全量测试 513 项通过、1 项跳过。应用依赖按仓库锁文件安装，没有修改其他包的锁定版本。

入口身份测试覆盖无认证头的浏览器会话、有效 Bearer、失效令牌、未配置账号和四类错误认证头。显式提供无效认证头时直接拒绝，不降级为浏览器 Cookie 身份，避免误记实际操作人。这些测试使用模拟 Auth 响应，不等同于完整 Supabase Auth 联调。

后续权限边界阶段新增 16 项测试，全量更新为 529 项通过、1 项跳过。能力清单只采用数据库返回的授权；缺项或空列表不再按页面角色补齐权限。非法类型、重复动作或不一致授权来源返回 503；查询错误和未认证响应均禁止缓存。权限查询抛出网络异常时返回安全的 503，不泄露传输细节、不执行业务 RPC。接口测试验证清单曾允许某动作后，执行前仍重新检查权限，撤销后返回 403。该阶段仍使用合成认证和 RPC 响应，不是员工真实账号联调，也没有修改线上授权或迁移。

认证异常阶段新增 15 项测试，全量更新为 544 项通过、1 项跳过。Bearer 验证遇到网络错误、408/429/5xx、SDK 可重试或未知错误时返回 `authentication_unavailable`（503），而明确拒绝的令牌仍为 401，未配置账号为 403。入口捕获客户端初始化、认证及账号解析抛出的异常，不返回异常原文、不切换账号。两个操作接口统一映射状态且禁止缓存；503 前不会调用业务 RPC。不自动重试、不生成新付款请求号，也不宣称先前请求未入账。此改进限外部操作入口；普通网页登录及共享账号资料解析返回错误的细分仍需后续处理，不等同于完整离线能力。

用户确认使用“振咏”后，选择名单及后端姓名校验不再接受“振勇”。远程只读核验：“振咏”关联两笔日租订单，旧“振勇”未关联日租订单；旧客户记录及历史迁移/审计原文保留，不做未经全面关联核对的身份合并或删除。

## 原生并发验收与本机安全

- 相同请求号的第二个连接确实等待事务锁，首笔提交后不会再次创建付款或审计。
- 同请求号改金额、换操作人的请求等待首笔提交后被拒绝。
- 两笔不同请求收款按订单锁顺序重新检查余额；合计超额时后笔被拒绝，合法的两笔保留各自实际操作人。
- 首笔回滚或其后端被中断时，等待者可接手原请求号；付款、流水、审计和应收不会留下半笔记录。
- 锁等待超时不会多写，恢复后使用原请求号可查询/恢复已提交结果。
- 收款先于冲销、冲销先于收款、两笔冲销争用同一原付款三个场景均保持最终账务一致，原付款只冲销一次。

开发依赖固定为 `embedded-postgres@17.10.0-beta.17`（提供原生二进制）、`pg@8.23.0` 和 `@types/pg@8.23.1`。它们仅供测试，不用于应用的数据库连接。原生运行器不接受外部数据库 URL：每次创建 `work/operator-postgres/run-*` 下的新集群，随机端口及临时密码，只监听 `127.0.0.1`，不创建系统账号、不载入 `.env.local`，并核对实际 `data_directory`。

子进程隐藏运行，测试完成或普通异常退出后关闭连接与测试服务器；仅清理经绝对路径校验的本次随机目录。已核验本轮结束后无残留测试服务器及数据目录。不要把此运行器改为读取生产 `DATABASE_URL` 或复用开发者的现有数据库。

原生套件需要普通操作系统用户及对应平台二进制。Linux root 环境会明确拒绝运行，不自动创建用户；支持的平台以 [运行包说明](https://github.com/leinelissen/embedded-postgres) 为准。

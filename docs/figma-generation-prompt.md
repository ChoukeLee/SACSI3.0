# SACSI Figma Generation Prompt

## 用途

这份提示词用于让 Figma AI、设计师、或其他 UI 生成工具理解 SACSI 的重构方向。可以直接复制，也可以按页面拆开使用。

## 总提示词

请为 SACSI 3.0 重新设计一套现代、统一、专业的房产运营管理系统 UI。

SACSI 是位于阿比让的房产运营系统，业务包括日租、长租、房屋出售、房源管理、客户档案、财务应收收款、审计日志和管理驾驶舱。用户包括前台、财务、管理者和老板。

设计目标不是营销网站，而是高频办公系统。界面需要克制、清晰、数据可信、操作响应快，适合长时间使用。允许完全抛开旧 UI 的视觉规则，但必须保留业务逻辑。

请优先设计桌面端 1440px，然后考虑 1024px 和 390px 的响应式版本。

视觉要求：

- 整体统一、干净、成熟。
- 不使用夸张渐变、装饰性大图、营销 hero。
- 颜色只服务状态和层级。
- 金额、日期、房号必须清晰。
- 表格密度要高，但不能拥挤。
- 卡片不能挤压按钮。
- 侧栏是主要详情和操作容器。
- 中文和法语文案都要能放下。

业务重点：

- 日租房只属于 11#公寓。
- 日租要支持已预订、已入住、已付款、未付款、非固定离店、已退房待清洁、维修等状态。
- 长租和出售页面应使用相似的信息结构：楼栋切换、KPI 卡片、KPI 明细抽屉、合同列表、合同详情抽屉。
- 财务页面必须强调应收、已收、未收、逾期和收款来源。
- 审计日志要清楚显示操作人、时间、操作、对象和摘要。

请先输出：

1. 设计系统基础：颜色、字体、间距、圆角、阴影。
2. 核心组件库：按钮、输入框、分段控件、KPI 卡片、表格、状态徽章、房间卡片、合同卡片、右侧抽屉。
3. 核心页面：日租业务页、长租合同页、出售合同页、房源总览页、财务应收页。

## 日租业务页提示词

请设计 SACSI 日租业务页。

页面目标：前台需要在一个页面中完成看房态、创建入住、确认预订、收款、续住、退房、清洁和维修。

页面结构：

- 左侧系统导航。
- 顶部工具栏。
- 页面标题“日租业务”。
- 今日摘要卡片：今日入住、今日离店、未付款、待清洁、维修。
- 主要操作工具栏：新建入住、复制今日房态、打印、日期切换。
- 日租日历主区域：房间行、日期列、入住条。
- 右侧订单详情抽屉。

必须展示状态：

- 空房。
- 已预订未付款。
- 已预订已付款。
- 已入住未付款。
- 已入住已付款。
- 非固定离店。
- 已退房待清洁。
- 维修。

关键要求：

- 日历是视觉中心。
- 订单条必须显示客户名和核心状态。
- 维修和待清洁不能是空白条。
- 欠款为 0 时不能显示红色待补缴。
- 侧栏操作区要清晰，主操作只能有一个。

## 长租合同页提示词

请设计 SACSI 长租合同页。

页面目标：让管理者从楼栋维度查看合同、月租规模、15天内应缴、待收未逾期、逾期金额，并快速进入收款或合同详情。

页面结构：

- 页面标题“长租合同”。
- 楼栋切换。
- KPI 卡片：生效合同、月租规模、15天内应缴、待收未逾期、逾期金额。
- 点击 KPI 后打开右侧明细抽屉。
- 合同状态筛选。
- 楼层分组合同卡片。
- 合同详情抽屉。

关键要求：

- KPI 卡片是可点击的，不只是展示数字。
- KPI 明细抽屉解释数字来源。
- 合同卡片底部按钮居中且间距稳定。
- 欠款、逾期、资料待补要有清楚状态。

## 出售合同页提示词

请设计 SACSI 出售合同页。

页面目标：让出售业务与长租业务拥有一致的信息结构，同时保留出售独有的合同总额、回款、过户和付款计划。

页面结构：

- 页面标题“出售合同”。
- 楼栋切换。
- KPI 卡片：生效出售、合同总额、已回款、待回款、逾期回款、已过户。
- KPI 明细抽屉。
- 出售合同列表或卡片。
- 合同详情抽屉。
- 付款计划和过户状态区域。

关键要求：

- 与长租页面同一种视觉语言。
- 付款计划清楚可追溯。
- 已回款、待回款、逾期回款不要重复表达。
- 不出现中英混杂或乱码。

## 房源总览页提示词

请设计 SACSI 房源总览页。

页面目标：让管理者快速理解各楼栋资产状态，并进入单个房间或特殊资产详情。

页面结构：

- 页面标题“房源总览”。
- 楼栋切换：11#公寓、5#公寓、6#公寓、7#公寓。
- 楼层切换，顺序为 G、0、1、2、3...
- 房源状态统计。
- 状态结构图。
- 楼层分组房间卡片。
- 房间详情抽屉。

特殊要求：

- 5#公寓 8 楼是科建集团自用办公室，应作为整层办公室卡片展示，而不是拆成 801、802、803、804、805。
- 某栋楼没有日租、待清洁等状态时，不显示无意义的状态筛选。
- 房源状态颜色要能区分空闲、长租、出售、维修、待清洁、自用。

## 财务应收页提示词

请设计 SACSI 财务应收与收款页。

页面目标：让财务快速核对应收、已收、未收、逾期、来源、客户、房号、备注和审计关系。

页面结构：

- 页面标题“应收与收款”。
- 金额 KPI：总应收、已收、未收、逾期、收款率。
- 收款结构图。
- Tabs：应收、流水、收据。
- 筛选栏：状态、来源、楼栋、日期、搜索。
- 财务表格。
- 收款详情抽屉。
- 欠款明细抽屉。

关键要求：

- 金额列右对齐。
- 房号、客户、备注不丢失。
- 表格完整显示，不裁掉右侧金额。
- 长备注可以截断，但必须能在详情抽屉查看完整内容。
- 已付清显示为成功状态，0 欠款不能显示为红色风险。

## 审计日志页提示词

请设计 SACSI 审计日志页。

页面目标：让用户清楚看到谁在什么时候做了什么，尤其是订单、收款、房源状态和 AI/业务助手操作。

页面结构：

- 页面标题“审计日志”。
- 筛选栏：时间、操作人、操作类型、对象、房号。
- 审计日志表格。
- 详情抽屉。

关键要求：

- 操作人必须显示为可理解名称，不能只显示短 id。
- 摘要必须中文化。
- 详情抽屉展示原始 metadata。
- 财务操作要更容易识别。

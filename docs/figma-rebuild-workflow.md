# SACSI Figma Rebuild Workflow

## 目标

这份流程用于把 `figma-ui-rebuild-brief.md`、`figma-component-spec.md`、`figma-page-blueprints.md` 变成实际 Figma 文件和后续代码改造计划。

重点不是一次画完所有页面，而是先建立可以复制扩展的视觉系统。

## 阶段 1：建立 Figma 文件结构

建议新建一个 Figma 文件：

`SACSI 3.0 UI Rebuild`

页面结构：

1. `00 Foundations`
2. `01 Components`
3. `02 App Shell`
4. `03 Daily Rentals`
5. `04 Contracts`
6. `05 Finance + Records`
7. `06 Mobile`
8. `99 Archive`

## 阶段 2：Foundations

先不要画业务页面，先确认基础视觉。

### 需要定义

- 字体
- 字号层级
- 页面背景
- 卡片背景
- 边框
- 阴影
- 圆角
- 主色
- 财务状态色
- 房源状态色
- 间距系统
- 图标尺寸

### 验收

- 中文和法语都能正常显示。
- 金额、日期、房号有稳定的数字样式。
- 背景和卡片能支撑长时间办公，不刺眼。
- 主色不能和风险色、收款色混淆。

## 阶段 3：Components

按组件优先级逐个画，不要一上来画完整页面。

### 第一批组件

1. Button
2. IconButton
3. SegmentedControl
4. Input / Select / DateInput
5. Badge
6. StatCard
7. RightDrawer
8. Table
9. RoomCard
10. DailyBookingBar

### 第二批组件

1. FinanceTable
2. ContractCard
3. StatusLegend
4. DonutCard
5. Toast
6. Skeleton
7. EmptyState
8. ConfirmDialog
9. PaymentSummary
10. AuditLogRow

### 验收

- 每个组件至少有 default、hover、active、disabled 状态。
- 组件命名和 `figma-component-spec.md` 一致。
- 组件可以支持中文和法语。
- 每个组件都能找到对应代码落点。

## 阶段 4：App Shell

先画系统外壳，再画页面。

### Desktop

- 左侧导航展开状态。
- 顶部栏。
- 当前页面激活态。
- 用户、语言、通知、收据扫描。

### Mobile

- 顶部栏简化。
- 底部导航或移动侧栏。
- 业务页面内容如何收窄。

### 验收

- Logo 不变形。
- 侧栏和顶部栏贴合。
- 页面抽屉不会和顶部栏产生灰色空隙。
- 当前页面状态清楚。

## 阶段 5：核心页面样板

优先画 5 个桌面样板。

### 1. 日租业务页

必须画：

- 正常日历视图。
- 点击订单后的详情抽屉。
- 新建入住抽屉。
- 欠款明细抽屉。
- 待清洁/维修/已入住/已预订状态。

验收重点：

- 日历是主视觉。
- 操作入口不拥挤。
- 状态条内有文字。
- 金额状态不误导。

### 2. 长租合同页

必须画：

- 楼栋切换。
- KPI 卡片组。
- KPI 明细抽屉。
- 合同卡片。
- 合同详情抽屉。

验收重点：

- KPI 点击后能解释数字来源。
- 合同卡片内容不被底部按钮挤压。
- 15天内应缴、待收未逾期、逾期金额三者区分清楚。

### 3. 出售合同页

必须画：

- 与长租一致的 KPI 卡片组。
- 出售详情抽屉。
- 付款计划。
- 过户状态。

验收重点：

- 出售和长租像同一套系统。
- 出售独有字段不硬塞进长租模板。
- 没有中英混杂和乱码。

### 4. 房源总览页

必须画：

- 楼栋切换。
- 楼层顺序：G、0、1、2、3...
- 房源状态结构。
- 房间卡片。
- 整层办公室卡片。
- 房间详情抽屉。

验收重点：

- 特殊资产可以整体展示。
- 无意义状态不显示。
- 房源状态颜色稳定。

### 5. 财务应收页

必须画：

- 金额 KPI。
- 筛选栏。
- 应收表格。
- 欠款明细抽屉。
- 收款详情抽屉。

验收重点：

- 表格完整平铺。
- 金额右对齐。
- 房号、客户、备注不丢失。
- 详情抽屉能承载完整备注和审计信息。

## 阶段 6：设计评审

每张核心页面都按以下问题评审：

- 这个页面最重要的业务动作是什么？
- 这个动作是否一眼可见？
- 当前页面是否存在多个主按钮？
- 颜色是否只用于表达状态，而不是装饰？
- 同类组件是否和其他页面一致？
- 金额是否可信、清楚、可核对？
- 中文和法语是否都能放下？
- 侧栏是否比弹窗更适合当前操作？
- 表格是否在小屏或窄窗口下仍然可用？
- 哪些内容应该折叠到更多操作？

## 阶段 7：代码落地

设计通过后，代码不要按页面直接复制 Figma，而是先改共享组件。

### 推荐顺序

1. `src/components/ui/button.tsx`
2. `src/components/ui/operational.tsx`
3. `src/components/ui/business-table.tsx`
4. `src/components/ui/sheet.tsx`
5. `src/components/room-card.tsx`
6. 日租日历组件
7. 长租列表组件
8. 出售列表组件
9. 房源列表组件
10. 财务列表组件

## 阶段 8：页面迁移

每次只迁移一个页面族。

### 页面族顺序

1. 日租
2. 长租
3. 出售
4. 房源
5. 财务
6. 客户
7. 管理驾驶舱
8. 审计日志

### 每个页面族的迁移步骤

1. 截图当前线上页面。
2. 对照 Figma 标注差异。
3. 修改共享组件。
4. 修改页面布局。
5. 验证业务操作。
6. 验证构建。
7. 推送。

## 阶段 9：旧样式清理

页面迁移后，清理以下内容：

- feature 文件中重复定义的按钮样式。
- 重复卡片布局。
- 重复表格壳。
- 重复侧栏结构。
- 英文历史备注直出。
- 乱码文案。
- 不再使用的旧设计文档约束。

## 不建议做的事

- 不建议先重画全部页面再落地。
- 不建议让 Figma 完全脱离真实数据。
- 不建议把日租复杂业务简化成普通酒店模板。
- 不建议把财务页面做成过度卡片化。
- 不建议为了美观隐藏审计、备注、欠款来源。

## 最小可行交付

第一轮 Figma 最小交付只需要：

1. Foundations。
2. 组件库第一批。
3. 日租业务页。
4. 长租合同页。
5. 出售合同页。

这 5 项完成后，就可以开始第一轮代码落地。

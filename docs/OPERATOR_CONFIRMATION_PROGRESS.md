## 第二阶段：账号确认与原子入账（本地实现，默认关闭）

2026-09-15 新增待确认记录、同账号确认页面，以及事务内的付款和确认审计。第一批仍只支持单笔、固定退房日期的日租截图收款，不包含批量或房租/物业费分账。

- `POST /api/operator/v1/confirmations/prepare` 继续只读预览。
- `POST /api/operator/v1/confirmations/drafts` 校验签名、账号、请求和最新快照后保存待确认单，返回专属页面地址；不写付款。
- `/operator/confirmations/[id]` 只向所属账号展示房间、金额、收据、余额、原始指令和实际账号。勾选核对后才能点击入账；没有自动提交或自动重试。
- 未登录时先登录，再返回原确认单；回跳白名单仅允许确认单路径，不接受外部网址。
- `POST /api/operator/v1/confirmations/[id]` 限同源 Cookie 登录；只接受确认单 ID，不接受替换金额、账号或原始业务内容。成功必须通过付款证据复查。
- 数据库按请求锁、确认记录锁、订单锁的顺序执行；过期、跨业务日、快照改变、权限撤销均拒绝。付款、账本、确认状态和审计处于同一事务，失败全部回滚。
- 同单重复确认不会新增付款；网络结果未知时保留原单重试，禁止换请求号重新录入。历史已执行页面只展示历史状态，不宣称重新验证了当前账务。

本地迁移 `20260915162247_add_operator_payment_confirmations.sql` 必须在付款完整性迁移 `20260915150854_harden_operator_daily_payment_integrity.sql` 之后部署。两者本轮均未应用到线上。

新增服务端开关 `SACSI_OPERATOR_CONFIRMATIONS_ENABLED=true`，默认未启用；仍需独立预览签名密钥。本轮没有配置真实密钥、开启线上入口或写入真实账务。

### 权限边界与未完成项

确认表启用 RLS，无客户端直接读写权限；公开 RPC 使用 invoker 包装，内部函数校验当前账号、动作权限和记录归属。按 Supabase/Postgres 技能检查了权限范围与锁顺序。

**这是账号确认，不是物理人工身份认证。** 同源 HTTP 防护是 CSRF 防护；持有该账号有效凭证的程序仍可能调用已授权的数据库 RPC。环境开关也只限制应用入口，不限制已部署的 RPC。不能把此设计宣称为“AI 无法确认”，若要求硬性区分自动化与人，需要独立确认凭据或第二人授权。

原截图动作接口仍不会因为 `confirmed: true` 或签名预览就执行付款。正式启用前仍需员工真实 Auth/RLS 验收、完整浏览器流程核验、部署审核及上述权限边界确认。此轮测试采用合成业务与模拟身份，不是员工验收。

接口第一批仅支持 `record_daily_payment` + `excel_screenshot`，单笔固定退房日期日租收款；批量、开放式入住、例外事项、长租/出售仍拒绝。请求结构沿用现有操作协议，先校验身份、版本、收款权限及数据库协议版本 2。

## 预览内容

服务端自行读取订单快照，不采用客户端提供的余额或快照。核对订单/房间、业务状态、唯一有效应收、客户/楼栋/币种/类别，以及历史收款合计与累计已收。返回本次金额、收款日期、收据号、房间、经办人 ID、前后已收/未收及识别指令。不调用模型，不额外推断财务规则。

同订单快照发现已有相同请求号时要求原号复查，不再次准备一笔付款；此处不是全数据库的请求号查重或完整账务审计，最终仍由原子交易负责。

## 预览凭证不是确认凭证

- 使用独立服务端 `SACSI_OPERATOR_PREVIEW_SECRET`（32 字节随机值的 64 位十六进制编码），不复用 Supabase Service Role，不使用 `NEXT_PUBLIC_` 前缀。示例配置只有注释，没有生成/保存真实密钥。
- HMAC-SHA256 绑定用途、实际账号、规范化请求摘要、数据库快照摘要、数据库项目及服务端版本；包含随机编号和时间。
- 有效期十分钟，跨 Africa/Abidjan 的业务日期也失效。修改金额、来源、指令、请求号、操作账号、快照或部署版本均无法沿用。
- 凭证包含账号 ID 与摘要，不包含识别原文、明文余额和财务行。签名提供完整性，不提供加密；不要记录或转发凭证。
- 返回 `preview_requires_human_confirmation` 和 `executionAvailable: false`。这是**预览完整性证明，不是人工同意**，也不是授权令牌。
- 将 `previewProof`、`confirmed: true` 塞回原收款接口仍只得到 `confirmation_required`，不能完成截图写入。
- 快照校验目前是独立校验函数/测试，不是事务锁内的写前门禁。不能用应用层“查询后比对”代替最终数据库原子校验。

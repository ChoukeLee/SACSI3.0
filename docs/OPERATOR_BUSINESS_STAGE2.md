## 可用流程与明确边界

| 操作 | 本地实现 | 边界 |
| --- | --- | --- |
| 新建预订 | 查询房间/经办人候选，固定住期、日价、客人姓名，创建预订及应收并确认 | 不猜人、不自动创建客户、不回填历史、不开开放住期 |
| 入住 | 当天已确认订单办理入住 | 本单不收款；不把入住+收款需求擅自拆开 |
| 调整日期/房价 | 展示原新住期、日价、应收及净收款，保留已存优惠 | 已入住不可回改入住日；不能把应收改到低于已收以隐式制造退款 |
| 预订换房 | 未入住、无收款预订及应收同步换房 | 已有真实财务历史不能当普通预订转移 |
| 录错房号纠正 | 支持未退房且无保洁历史订单，含已入住/已收款；同步订单、付款、账本、应收及付款附件房间关联 | 金额、收据编号、经办人不变，旧归属快照保留在审计；拒绝冲突和不一致账务 |
| 取消 | 取消无收款且未入住预订 | 已收款取消需协助核对，不删除收款 |
| 误入住纠错 | 管理员撤销无收款、无保洁历史的误入住 | 不冒充真实客户退房 |
| 错误收款冲正 | 指定原收款、完整原因，保留原记录，新增负向流水 | 不是实际退钱；已有实际退款的订单禁止直接整笔冲正原收款，旧页面同样受保护 |
| 实际退款 | 已退房 XOF 订单，明确最终应收、实际退款金额、日期、方式与原因；保留原收款，新增 daily_refund 与支出账本 | 仅记录已经实际退的钱，不发起银行转账；不超过已收减最终应收；不覆盖长租/出售退款或跨币种退款 |
| 长租/物业费/出售收款 | 复用已发布的查询、应收选择、整批分账和本人确认流程，并复跑本地联调 | 多合同、缺失账期、不平账仍先问清楚，不新造旁路写入 |

## 安全与恢复

- 新增私有确认表及 `operator_booking_operation` invoker 入口，内部受限函数空 search_path。私有表 RLS 开启，无客户端直读；匿名/service_role 不可执行新入口。
- 实时账号、动作、角色、房间权限核对；高风险仍限定 admin，没有因账号已创建而扩大权限。经办人、客人、实际操作账号分别保存。
- 预览只读；签名绑定账号、请求、完整快照和服务器版本；网页确认拒绝 Bearer 与跨源。数据库中独立复核权限、时效、快照和冲突。
- 原号串行锁、记录锁、全部成功或回滚、完成后不重复执行。历史完成响应 verified=false，不宣称复查了后续账务。数据库 RPC 仍是普通已授权账号可调用的接口，网页点击限制不是对同一账号令牌持有人的隔离保证。
- 保留 0.4.0 待办机制，新增 booking_operation 类型，先加密落盘再准备。旧版本不能处理新类型，回退期间保留密文，恢复使用 0.5.0。
- 日租面板单列实际退款；审计摘要区分冲正/退款，并显示房号纠正前后、实际登录人和业务经办人。

# 工程维护、发布与交接

工程重构及灾备演练最初仅在本地完成；2026-09-24 已取得协调发布授权，长租生产迁移已应用，应用发布状态见 [长租事务化](LEASE_ATOMIC_TRANSACTIONS.md)。本轮不替换员工连接器，不新增真实财务测试记录。

## 开发检查

1. `git status --short` 检查用户已有改动；不要提交 `.env*`、work/、output/、tmp/ 或员工会话。
2. `npm ci` 安装锁定依赖。`npm run lint`、`npm run format:check`、`npm run check:daily-rental-rules`、`npm run typecheck`。
3. `npm test` 跑普通回归；`npm run test:operator-concurrency` 跑一次性本地原生 PostgreSQL（含从零重建）。无需真实账号或云数据库连接。
4. 有隔离 Docker 栈时，`node scripts/start-local-operator-web.mjs --build` 做不读取生产环境文件的生产构建；`npm run build` 仅在明确配置的环境中使用。
5. 更改财务、确认或授权时，增加行为/数据库测试，不能仅增加源码字符串匹配。新迁移必须在重建清单分类：结构增量或明确排除的真实业务数据迁移。

## 模块规则

- 展示层不得导入特权数据库客户端；纯规则层不得依赖页面、网络或数据库。
- 兼容入口只转发，规则只有一个明确的维护位置。共享标签不是共享授权。
- 财务金额、币种、日期、对象和期间不明确时必须澄清；退款与录错冲正保持不同业务操作。
- 合同/订单经办人不等于实际登录操作人。确认必须属于当前登录账号，重复请求沿用原 requestId。
- 不改变现有业务规则的拆分与业务行为修改分开评审；遗留多步写入不能仅靠拆文件获得原子性。

## 发布与回退

1. 检查 diff、排除无关数据文件；保留最后已验证提交、线上部署 ID、当前连接器包版本及哈希。
2. 按用户发布授权推送。等待 GitHub CI 和 Vercel 成功，再用普通账号进行只读能力/身份检查；不能把 push 成功当上线成功。
3. 后续长租事务化新增一份 SQL 迁移，发布顺序与停写窗口见 [长租事务化](LEASE_ATOMIC_TRANSACTIONS.md)。数据库变化应备份后先兼容扩展、再发布应用，禁止为了回退应用直接删除财务数据或列。
4. 应用故障优先恢复上一验证部署；连接器回退使用完整旧目录，不覆盖个人密文待办。新业务待办与旧包不兼容时暂停该业务，保留原号等待恢复。
5. 结果未知时先按原 requestId 查询，不新开收款。恢复后核对订单/合同、应收、收款、流水、房态和审计，不以单个页面成功提示替代核验。

## 重建及恢复边界

`supabase/baselines/rebuild-manifest.json` 固定结构快照和逐个审核的增量哈希。测试从空数据库开始，平台 Auth 使用测试桩；这证明应用结构和业务 RPC 可重建，不证明完整云平台灾备已演练。历史人员授权/客户订单修复不当作测试种子重放。

旧 `setup-local-full-schema.mjs` / `check-local-full-schema.mjs` 是 9 月 16 日基线工具，不再作为当前完整结构验收入口。当前使用 `test:db-rebuild` 与完整原生回归；旧工具保留历史复现用途，并要求显式历史模式。不要在云端执行本地重建脚本。

生产恢复需要另行核验数据库业务备份、Auth 身份、Storage 凭证对象、配置密钥、恢复点和恢复时长；未经真实演练不得声称可完整恢复。

2026-09-23 已完成真实快照的本地数据库/Auth/Storage 恢复演练：73 表、18,890 条记录及结构哈希一致，原账号登录与合成文件恢复通过，演练容器已停止。异地备份/独立密钥保管、定时任务替换、整站云端切换尚未完成。范围与证据见 [灾备演练记录](DISASTER_RECOVERY.md)。

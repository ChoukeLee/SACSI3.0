# CIMAC finance completion contract

Dedicated `cimac_finance` workflow, protocolVersion `1.0`, connectorVersion `0.9.0`. Existing maintenance v1 and native collection wire versions stay unchanged. Normal authenticated CIMAC administrator only. At most 30 operations / 100 parts. All original receipt sources are retained as `excel_screenshot`.

Request: `{requestId, protocolVersion, connectorVersion, originalInstruction, inputSource, operations}`. UUID is fixed for the batch. Strict keys, exact positive whole-XOF decimal strings, CNY decimal strings up to two places, valid nonfuture receipt dates, cash XOF receipts only. Every operation includes a nonempty `annotation`.

## Operations

- `collect`: `{type, customerId, customerName, category, receipt, parts, servicePeriod?, annotation}`. category is `lease_deposit` or `property_fee`. `receipt={amountXof,paymentDate,paymentMethod:'cash',externalReceiptNo?,sourceText}`. `parts=[{contractId,amountXof,discountXof?}]`. Every exact contract must be a CIMAC commercial-shop unstarted draft, belong to the same customer, have no conflicting current lease, and have verified payment/ledger history. Parts sum to the one physical receipt. Deposit has no discount or servicePeriod and cannot exceed each exact contract's known remaining deposit. Property requires the full active annual fee-rule period in `servicePeriod={start,end}`; each amount+explicit discount must equal that unit's standard annual fee and there must be no existing bill/payment for the same coverage. No inferred split.
- `new_deposit`: `{type, customerName, receipt, units, annotation}`. `units=[{unitNo,monthlyRentXof,depositXof,amountXof}]`. Existing available physical shops only; no duplicate/current customer or current lease, no inherited old customer's funds. Deposit=3*monthly rent; explicit received parts may be partial and sum to receipt. Create a new customer and unsigned pending-opening draft per shop, no signing/start/end dates, no rental bill, no paid-through date. Use confirmed project policy: rent from 2028-04-01, free 2027-04-01..2028-03-31, property rate 900 XOF/sqm/month for that annual period. Each part generates a normal lease_deposit payment and one liability_in ledger; external receipt metadata groups the split, system financial numbers remain autogenerated. No invented collector.
- `reclassify`: `{type,paymentId,expectedSourceType,targetSourceType,amountCny,annotation}`. Only a whole original converted CNY lease_deposit/lease_rent payment may switch to the other classification. Must have exactly one matching original ledger, no reversal/refund/allocation, no native/unknown valuation, correct current unstarted CIMAC draft. Preserve IDs, dates, amounts, currencies, historical FX, receipt numbers, methods, source_id/customer/unit and all other cash facts. Change only payment.source_type; change only ledger.direction/category/description. Append explicit current classification notes to the contract/unit, retaining historical text. Capture complete immutable before/after evidence and audit. No new payment/ledger for reclassification and no fake refund/recollection. Recompute deposit flag from actual known historical valuation, not guessed FX.
- `identity`: `{type,customerId,customerName,units,holderName?,managementNames?,annotation}`. `units=[{unitNo,expectedHolderName:string|null}]`. Exact same customer's current CIMAC drafts only. holderName, if present, must equal the existing confirmed customerName; align only the scoped unit labels, never rename/merge the global customer. managementNames adds a documentary note for different managers of the same shop, does not replace the main customer, alter money, or change unrelated units. At least one action required.

Shared safety: exclude warehouse and old/current 231. Reject duplicate targets; receipt operations cannot collide with identity/reclassify unit targets in the same batch except identity is allowed on the same customer's collected units if deterministic and explicitly same-scope (prefer separate type-specific uniqueness sets). Fail the whole batch on any mismatch. No arbitrary SQL/table/field selection. Any added payment/ledger and corrected classification are protected from legacy direct table tampering, while future authorized controlled correction remains possible.

## Property receipts / concessions

For each property part create one paid property_fee receivable at the explicit annual period's start (the confirmed fee policy date, NOT the receipt date), with amount and paid amount equal to net charged/received, explicit service_period_* facts from the receipt, and a title/source noting standard gross and approved discount. No future rent receivables. Create a normal property_fee payment and its unique income ledger; link the paid fee receivable with the verified allocation helper. Store the explicit discount/service-period proof in the new private request/audit evidence; do not create discount cash or reduce the standard 900/sqm price rule. Existing receivables remain byte-for-byte unchanged.

## RPCs / atomicity

Public invoker wrappers: `cimac_finance_protocol_version() -> 1`, `can_execute_cimac_finance() -> boolean`, `preview_cimac_finance(p_request)`, `execute_cimac_finance(p_request,p_snapshot,p_expires_at,p_deployment)`, `find_cimac_finance(p_request_id)`. Private implementation independently rechecks normal authenticated admin+project ACL, request identity, locks, full-scope CAS fingerprint, expiry/deployment, duplicate physical receipt facts and rollback. Private journal includes exact input and full before/after state. Public/anon/service_role execute denied; authenticated execute only on named wrappers, private tables default-deny.

Preview result: `{status:'previewed',requestId,operationCount,snapshot:{fingerprint,requestHash}}`, readOnly=true/verified=false at HTTP.

Execute result: `{status:'completed',verified:true,requestId,actorId,request,operationCount,auditId,paymentIds,operationResults,verification,idempotent:false}`. Per-operation results contain `{index,type,customerId,unitIds,contractIds,paymentIds,ledgerIds,receivableIds}`. `verification={version:1,actorId,checks,payments,ledger,receivables,contracts,units,reclassifications,audit}`. Evidence arrays contain full raw snake_case public rows; reclassifications contain `{paymentBefore,paymentAfter,ledgerBefore,ledgerAfter}`. `audit={id,actorId,requestId,channel:'external_codex',authorization:'explicit_instruction'}`. Checks are true for `scope`, `payments`, `ledger`, `receivables`, `contracts`, `units`, `cashFactsPreserved`, `audit`, `exclusions`.

HTTP and connector must independently check exact request/actor, operation counts, per-part payment source/amount/date/method/currency/FX/system reference, matching unique ledger rows and direction/category, new unsigned contracts and deposit flags, property net/gross/discount coverage and paid bills, identity labels, immutable cash facts and exact allowed reclass changes. A bare verified flag is never sufficient. Historical find/retry is always `completed_previously` with verified=false and never replays.

Production business requests, customer identities, physical receipt images and post-execution evidence are kept in the operator's local uncommitted output directory, never embedded in this public repository. Automated tests use synthetic identities and receipts. Completed historical batches and out-of-scope expenses are never replayed or included in an execution request.

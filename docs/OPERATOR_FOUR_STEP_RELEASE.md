本轮交付为账号技术准备、截图收款校验、审计可追溯性、遗留清理与备份核验。以下区分自动验收与必须由人完成的环节，不能仅凭构建成功宣称业务已验收。

## 1 使用准备与安全验收

颖、黄姐的独立账号、角色、能力目录、个人待办、审计和财务读取完成只读技术核验，见 [员工使用准备](OPERATOR_USAGE_READINESS.md)。普通账号不得伪造 actor；确认必须是本人网页登录，Bearer 不能代替确认；请求幂等、退款/冲正、跨账号和并发防护保留。

本地完整普通测试和原生 PostgreSQL 测试覆盖合成业务，不写生产账务、不替员工确认。本人连接器登录、真实操作习惯与业务接受度仍需员工验收。

## 2 截图分账与重复录入防护

- 分账只接受明确整数 XOF、真实应收余额和可收状态。空白、null、布尔值、负数、小数、指数等异常账务金额不当作零；明确的数据库小数格式 `100.00` 可按整数读取。
- 已结清、取消、历史待核实、排除项或非 XOF 不生成分账建议；分项与总额不平继续询问。
- 行号空白及 Unicode NFC 统一用于重复比较；应收 UUID 大小写一致，输入数据不悄悄重写。
- 对有收据号的批次，准备和创建确认单前，使用当前普通账号分页读取同一合同/订单可见的历史收款。相同收据号命中后返回 `duplicateCollectionReceipt`，不创建新确认单；查询失败返回 503，保留原请求号。
- 同一新批次可包含共用一个收据号的不同目标；不把不同合同的同号收据当作全局唯一。已有分次使用、退款或纠正过的同号记录，需要先核对历史分账，不能自动绕过。
- 无收据号无法证明截图未曾录入；这不是全局数据库唯一约束或图片指纹识别。状态恢复接口及原确认单的幂等重试不变。金额/日期相同不能作为真实重复的充分证据。

## 3 财务审计核对

上线身份记录筛选和维护渠道标签；详情、搜索、CSV 同步。维护渠道来自历史记录值，不证明操作人或授权有效。缺少账号不猜填经办人或当前操作者，不显示某位操作人的角色。当前名称目录只作辅助，目录故障不能抹掉原账号证据；目录查询分批限制 URL 长度。

黄姐不用新增逐笔手工审计动作。可按账号、渠道、身份状态、日期、房号、请求编号及原始指令查阅。

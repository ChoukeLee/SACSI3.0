# 财务口径规范（Finance Metrics Spec）

更新时间：2026-10-15。本文件描述当前代码的语义约定，**不表示本轮迁移、生产发布或员工业务验收已完成**。具体状态见发布记录和 `PRODUCT_RENEWAL.md`。

## 1. 首要原则：现金和应收核销不是同一个数字

此前版本把“已收”同时用作现金收入和应收已核销，又要求所有金额使用一个计算引擎，容易把收款日期、应收到期日、押金、费用和退款混为一谈。本次明确分开：相同语义必须一致，不同语义必须各用自己的读模型，不强求所有财务卡片数值相同。

系统是经营台账，不是完整复式会计 ERP。净收款、经营现金净额均不等于利润。

| 指标 | 数据及定义 | 时间基准 |
|---|---|---|
| 已录经营收款 | 已明确分类的经营现金流入；不含押金和非现金抵扣 | 实际收款日 |
| 净收款 | 经营收款减明确的真实退款及经验证的纠错冲正；不扣经营费用 | 各资金事件记录日期 |
| 经营现金净额 | 已录经营收款减已录经营支出（含明确退款），不含押金负债变动 | 实际收付日期 |
| 已核应收 | 当前系统管理、未取消的应收总额 | 应收到期日或当前范围 |
| 应收已核销 | 同一应收范围内的 `paid_amount_xof`；不是本月现金收入 | 应收范围对应的当前核销余额 |
| 已建应收未收 | 每条应收 `max(0, amount_xof - paid_amount_xof)` 后相加 | 当前范围 |
| 到期未收 | 已建应收未收中 `due_date <= 今日` 的部分 | 截至今日 |
| 逾期 | 已建应收未收中 `due_date < 今日` 的部分 | 截至今日 |
| 应收核销比例 | 同一应收范围的已核销金额除以应收金额 | 明确标注的应收范围 |
| 押金实收 / 实退 | 已录押金现金流入、流出，单列负债，不当作租金收入 | 实际收付日期 |

兼容接口 `FinanceMetrics.collected` 的含义是“应收已核销”；旧字段名不能用来推断它是现金收入。

## 2. 应收管理范围和未知状态

| 管理状态 | 当前管理余额 | 展示原则 |
|---|---|---|
| `managed` | 计入 | 当前已核实、系统持续管理 |
| `historical_pending` | 不计入 | 历史待核对，独立保留，不自动清零或结清 |
| `excluded` | 不计入 | 排除原因保留，不能混入经营余额 |
| `cancelled` 应收状态 | 不计入 | 保留历史，不计入当前管理金额 |

- 没有已核应收不等于没有欠款，也不等于合同款已付清。合同页显示“未建已核应收 / —”。
- 部分合同有应收、部分没有时，汇总只展示已建立的范围，并说明未覆盖合同数。
- 读取失败不能返回成功的零金额、空账目或“数据质量良好”。
- 单条超付不得被总额相减用来自动抵销另一条欠款。核销或转款必须由明确业务动作完成。
- 合同总价、合同月租规模不是已建应收，更不能用 `合同总额 - 所有付款` 代替已核应收未收。

## 3. 时间范围

| 范围 | 含义 | 必须说明 |
|---|---|---|
| 期间 | 按明确发生日期选取区间 | 现金按收付日，应收按到期日，退房统计按退房日 |
| 截至 | 当前存量或到指定日期的应收范围 | 应收当前核销余额不代表还原了那个历史日期的余额 |
| 累计 | 全量已录、可确认范围 | 不得只取最近 100 / 200 条却称累计 |

`computeFinanceMetrics(receivables, { scope: "period", period: "YYYY-MM" })` 的期间过滤依据 `due_date`。返回的 `collected` 是这些应收的当前核销值，**不是这一个月收到的现金**。

到期日当天属于到期未收，但不是逾期。历史报表不能根据当前房间数乘历史天数，或把未来预订当成实际入住来制造入住率。历史可售房晚容量未经确认时，保留已识别实际房晚并明确容量不足，不给假精确百分比。

## 4. 现金、退款、冲正与外币

### 4.1 现金分类

- 依据结构化 `source_type`、`request_kind`、原交易关联及必要证据分类；备注文字不作为退款授权或金额方向证据。
- `payment_method = offset` 为非现金抵扣，不能计入收款增长。
- 押金收入和押金退还单列；押金扣除不自动当成现金退款。
- 合同“佣金已付”布尔值不代替逐笔付款凭证，不据此伪造一笔现金支出。
- 手工台账记录与真实收款分开：仅在存在关联付款、可核对项目归属及结构化收入方向时进入首页收款；仅有账本而没有付款的记录保留在财务流水，不自动证明现金已收。手工押金方向仍排除于经营收款之外。
- 未识别的负数、缺失历史汇率、无法核验的冲正等保留原记录，现金统计明确未纳入数量。

### 4.2 日租严格读模型

`daily_receipts_read_rpc` 统一日租汇总、趋势、明细和导出。真实退款与纠错冲正分开；冲正核验原收款，历史部分退款还需验证对应支出证据。跨月退款/冲正留在其实际事件月份，不改写原月份。

首页经营快照及报表复用此分类，不重新遍历最近几百条日租付款另算一套。无可纳入记录的月份标记“无记录”，不代表业务规模为零。

### 4.3 多币种

- 保存原币金额、币种和交易历史汇率；不能使用当前汇率重算历史交易。
- XOF 汇率必须是 1，非 XOF 必须有正、有限的历史汇率。
- 合同现金展示沿用已存在原子事务的精度：逐笔按历史汇率折算，并以十进制规则保留两位 XOF 后再汇总；不能擅自取整数，也不能先汇总原币或浮点乘积再统一取整。日租严格读模型已有整数 XOF 约束，不因此放宽。
- 原币金额仍可单列查看，不根据某一笔付款汇率倒推出整个合同的“原币合同总额”。
- 列表及主要金额使用完整 XOF，中文和法语都明确单位；“万西法”仅用于标明单位的录入控件，不隐式改变保存金额。

## 5. 当前模块职责

| 模块 | 职责 | 不负责 |
|---|---|---|
| `finance/metrics.ts` | 已核应收、核销、逐条余额、逾期 | 真实现金分类和按收款日统计 |
| `contracts/contract-list-model.ts` | 按合同组织已核应收、搜索排序、未知状态 | 写账、自动分账、真实现金推断 |
| `contracts/contract-cash-model.ts` | 合同已录经营现金及押金分别汇总 | 日租严格退款验证、历史核销补全 |
| `daily_receipts_read_rpc` | 日租收款/退款/冲正的严格统一统计 | 修改历史账务 |
| `management_operating_snapshot_rpc` | 当前项目、同一 SQL 快照的经营现金和管理余额 | 跨项目自动合并、利润核算 |
| `finance_read_rpc` | 同一范围的财务列表、汇总和导出 | 把经营流水当作完整复式总账 |
| `resolveLeaseOverdue` | 合同缴费覆盖的跟进提示 | 自动生成已确认债务 |

长租/出售合同页的现金与核销分栏；`max(付款净额, 应收核销)` 不再是合法对账方式。合同列表、详情与打印摘要的已核应收口径必须一致。

首页按当前项目及账号权限显示本月净收款、到期未收和合同/资产关注事项。日租只占业务概览的一行，详细日历及收款分析保留在日租模块。CIMAC 只租不卖，不复用住宅日租规模或入住率。

## 6. 验收约束

- 读取同一语义的列表、汇总、详情、导出必须使用相同分类、项目与时间过滤。
- 覆盖管理状态、到期日边界、超付、缺失应收、跨币种历史汇率、非现金抵扣、退款/冲正和权限变化。
- 新读模型需通过原生 PostgreSQL / RLS 回归，而不只通过字符串或浏览器模拟。
- 推送、迁移、生产部署、真实账号只读页面核验、业务人员实际验收分别记录；不得互相代替。
- 历史账期、实际收款人和缺失核销的修复仍须原始凭证及明确授权，不因优化展示自动修改真实财务数据。

### 后续 RPC-only 访问收拢边界

当前已核实的项目行策略为 RESTRICTIVE，不存在仅凭 `FOR ALL` 就能断言的 OR 绕过角色问题。但旧财务表仍允许指定业务角色直接 DML，尚未做到全部金额变动只能经原子 RPC。本轮新增事实守卫不等于已经收回所有旧表写权限。剩余 invoker、兼容迁移及隔离验收方案见 [财务访问边界复核](FINANCIAL_ACCESS_REVIEW.md)；不可在未迁移真实调用入口前直接批量 revoke，亦不可用批量 SECURITY DEFINER 替代授权审核。

## 7. 历史决策记录（保留，非当前发布证明）

2026-08-14 / 2026-08-15 的原始确认包括：首页同时关心本月收款与当前风险；历史待核不计入当前余额；长租按已缴至推算的值须标“预估”；“结算”保留为退房/退租等动作名。

当时提出统一“已收”等叫法及单一引擎的方案，是为解决多套口径混用，并不要求把现金与核销合并成同一金额。本次保留上述业务意图，废止不准确的等价关系和“所有金额只能出自同一函数”的技术表述。

此前迁移建立了 `management_status`、历史待核范围以及严格的到期日边界；历史记录中的步骤勾选与测试数量只代表当时的检查，不能作为此次整体更新的上线或验收证明。完整原稿保留在 [2026-08 财务口径历史稿](finance-metrics-spec-20260815-history.md)。

# 财务口径规范（Finance Metrics Spec）

> 状态：已确认（业主确认三项决策，见文末「决策记录」）
> 目的：统一「应收 / 已收 / 未收 / 逾期 / 回款率」的唯一定义与时间轴，作为后续所有财务页面的唯一依据。
> 原则：先定口径，再统一计算，最后才调排版。本文档是阶段 3（报表/提醒/多币种）的前置依赖。

---

## 1. 现状问题（为什么需要本规范）

当前同一批财务概念存在 6 套独立计算 + 4 种叫法 + 3 个时间基准混用：

| 页面 | 卡片 | 实际口径 | 问题 |
|---|---|---|---|
| 首页 | 本月应收/已收/未收/逾期 | 截至本月底的累计（as-of） | 标签写「本月」，语义却是累计，误导 |
| 日租 | 本月已收 / 当前欠款 / 本月结算 | 已收=按付款日(本月)、欠款=截至今日、结算=按退房日(本月) | 三种时间基准挤一行 |
| 长租 | 月租/已收/未收/逾期/生效数 | 累计，未收/逾期混入合同推算的估算值 | 「预估」未标注，与真实应收混淆 |
| 出售 | 生效/合同总额/已回款/待回款/逾期回款/已过户 | 累计 | 「回款」一词与「已收」并存 |
| 房源 | 累计应收/累计已收/未结金额/逾期金额 | 累计 | 命名相对清晰，但与其他页不一致 |

根因：应收/已收/未收/逾期没有全局唯一含义，本月/截至/累计没有显式区分。

---

## 2. 核心词汇表（唯一、全局强制）

以下 5 个词是唯一合法财务指标，全系统不得再出现其它同义别名。

| 标准词 | 唯一定义 | 计算公式 |
|---|---|---|
| 应收 | 应收取的总额（含已收+未收） | Σ(应收单.amount_xof)，排除 cancelled |
| 已收 | 实际收到的现金净额（收款 − 退款/冲销） | Σ(收款.amount)，含负向冲销 |
| 未收 | 尚未收到的余额 | 应收 − 已收（≥0） |
| 逾期 | 未收中，已过到期日的部分 | Σ(max(0, amount−paid) where 到期日 < 今日 且 未结清) |
| 回款率 | 同一期间内的回收比例 | 已收 ÷ 应收（应收为 0 时为 0） |

### 2.1 别名废除表（改名映射）

| 现名 | 改为 |
|---|---|
| 已回款 / 实收 / 到账 | 已收 |
| 待回款 / 待收 / 欠款 / 未结 | 未收（指余额时）/ 逾期（已过到期日时） |
| 结算（用于财务卡片） | 移除；「结算」只保留在具体动作名：日租「退房结账」、长租「退租结算单」、出售「中介费结算」 |

### 2.2 关于「结算」的特殊说明

「结算」是动作不是金额指标。财务卡片一律不使用「本月结算」这类金额；日租页当前「本月结算」卡片应正名为「本月退房结账额」（= 本月退房的订单最终额），并明确它是流量指标。

## 3. 时间轴三态（必须显式标注）

每个金额指标必须明确属于以下三者之一，且一个页面/一组卡片内只允许一种主口径：

| 口径 | 含义 | 适用场景 | 标注方式 |
|---|---|---|---|
| 期间 Period | 按业务发生日（收款日/到期日/退房日）切本月/本季 | 月度流量：本月收了/该收多少 | 前缀「本月」，角标注明按哪个日期 |
| 截至 As-of | 截至今天的存量 | 风险视图：现在欠多少、逾期多少 | 标注「截至今日」 |
| 累计 Cumulative | 历史全量 | 合同总额、房源档案 | 前缀「累计」 |

关键规则：
- 「逾期」本质上只能是 As-of 口径（存量），不出现「本月逾期」这种混淆；若确要本月维度，用「本月到期且逾期」并标注。
- 每个金额卡片必须有一行小字口径说明（如「本月 · 按收款日」「截至今日」），否则视为未完成。

## 4. 各页面卡片口径对照表（目标态）

### 4.1 首页（工作台）
> 采用「本月现金流 + 当前风险」组合，不展示业主无法确认的历史累计欠款。

| 卡片 | 标准词 | 口径 | 数据源 |
|---|---|---|---|
| 本月已收 | 已收 | 本月，按实际收款日；退款冲减，经营支出不冲减 | payments |
| 已确认未收 | 未收 | 到期日 ≤ 今日 | receivables(managed) |
| 逾期 | 逾期 | 到期日 < 今日 | receivables(managed) |
| 15天内应收 | 应收 | 明日到未来15天 | receivables(managed) |

- 首页不展示累计应收、累计已收或累计回款率，避免未核实旧账影响经营判断。
- 四张卡片和各自侧栏必须使用完全相同的数据行，卡片金额必须等于侧栏合计。

### 4.1.1 管理口径

| 状态 | 含义 | 首页/业务KPI |
|---|---|---|
| managed | 当前已确认、由系统持续管理 | 计入 |
| historical_pending | 历史遗留、金额或责任尚待核实 | 不计入，仅在财务页独立查看 |
| excluded | 无效、测试或非经营项目 | 不计入 |

### 4.2 日租
> 拆成两组，禁止三种时间基准混行。

| 组 | 卡片 | 标准词 | 口径 | 按哪个日期 |
|---|---|---|---|---|
| 本月流量 | 本月已收 | 已收 | 期间(本月) | 收款日 |
| 本月流量 | 本月退房结账额 | 应收(退房订单) | 期间(本月) | 退房日 |
| 截至今日 | 当前未收 | 未收 | 截至今日 | — |
| （可选）| 当前逾期 | 逾期 | 截至今日 | — |

- 现有「本月结算」→「本月退房结账额」。
- 现有「当前欠款」→「当前未收」。

### 4.3 长租
> 主口径：截至今日。

| 卡片 | 标准词 | 口径 | 说明 |
|---|---|---|---|
| 生效合同数 | （非金额） | 截至今日 | 状态=active 的数量 |
| 月租合计 | 月租 | 累计 | 生效合同月租之和 |
| 未收 | 未收 | 截至今日 | 真实应收余额 |
| 逾期 | 逾期 | 截至今日 | 真实应收中已过到期日 |
| 下一期应收(预估) | 应收 | 截至今日 | 必须加「预估」角标，与真实应收区分 |

- 关键修正：resolveLeaseOverdue 里由合同 paid_through_date 推算的下一期租金是预估，展示时加灰色「预估」标，不计入未收/逾期主数字。

### 4.4 出售
> 主口径：累计。

| 卡片 | 标准词 | 口径 | 说明 |
|---|---|---|---|
| 生效合同数 | （非金额） | 截至今日 | — |
| 合同总额 | 应收(总额) | 累计 | 全部出售合同总价 |
| 已收 | 已收 | 累计 | 净收款 |
| 未收 | 未收 | 累计 | 合同总额 − 已收 |
| 逾期 | 逾期 | 截至今日 | 已过约定付款日的未收 |
| 已过户数 | （非金额） | 截至今日 | — |

- 「已回款」→「已收」；「待回款」→「未收」；「逾期回款」→「逾期」。

### 4.5 房源档案
> 主口径：累计（已相对清晰，仅统一用词）。

| 卡片 | 标准词 | 口径 |
|---|---|---|
| 累计应收 | 应收 | 累计 |
| 累计已收 | 已收 | 累计 |
| 未收 | 未收 | 截至今日 |
| 逾期 | 逾期 | 截至今日 |

## 5. 单一计算引擎（目标架构）

新建 src/features/finance/metrics.ts，作为唯一金额聚合入口，五处页面全部改调它。

    export type MetricScope = "period" | "asOf" | "cumulative";

    export interface FinanceMetrics {
      receivable: number;     // 应收
      collected: number;      // 已收（净额）
      outstanding: number;    // 未收
      overdue: number;        // 逾期
      collectionRate: number; // 回款率
      count: number;
    }

    export function computeFinanceMetrics(
      input: { receivables: ReceivableRow[]; payments?: PaymentRow[] },
      options: { scope: MetricScope; period?: string; asOfDate?: string },
    ): FinanceMetrics;

约束：
- 应收/已收/未收/逾期/回款率只能由本函数产出，禁止页面内再各自 for 循环累加。
- 已收必须含负向冲销（退款），与总账的 income−expense 净额对得上。
- 逾期 = 未收中 due_date < asOfDate 的部分。

### 5.1 现有 6 套逻辑的去留

| calculateReceivableSummary (finance/receivable-summary.ts) | 合并进 metrics.ts |
| summarizeLeaseReceivables (lease) | 合并；预估部分单独暴露为 estimatedNextDue，不入主指标 |
| resolveLeaseOverdue (lease) | 保留，但返回值标记 source: "contract" = 预估 |

| 出售 dashboardStats / getContractSummary | 改调 computeFinanceMetrics |
| 房源 unit-profile-view 内联累加 | 改调 computeFinanceMetrics |

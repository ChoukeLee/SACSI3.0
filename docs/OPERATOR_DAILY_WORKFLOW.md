# 日租组合业务：本地执行闭环（2026-09-23）

状态：本地开发，未推送、未部署、未替换已安装的 0.2.0。源码连接器版本为 0.3.0；不代表 0.3.0 已发布。

## 已完成

- `search_daily_bookings` / `POST /api/operator/v1/bookings/search`：楼栋、房号必填；入住日期范围、客户姓名、XOF 金额可选。通过本人权限和 RLS 同时读取当前、未来、历史状态，保留不匹配候选与备注，标明金额匹配的是整单应收还是未收余额，不按最新日期自动选单。
- 单次最多返回 200 条；多一条即明确截断，禁止宣称唯一命中，须缩小日期范围。没有匹配线索不等于不存在订单。客户关联显式使用 customer_id 外键，不与 booking_agent_id 混淆。
- `plan_daily_change` / `POST /api/operator/v1/bookings/plan`：固定住期已入住订单的续住收款/退房收款完整影响方案。日期、金额、方式缺失时列出待确认项，不默认现金或今天。展示住期、应收、实收、欠款、退房与清洁影响，历史欠款不混入。
- 已存储的整单优惠日价保留；额外折扣、特殊计价、开放住期、账务不一致、超额收款/可能退款转人工协助。备注是数据，不是执行指令。
- 查询和影响方案接口保持只读；`plan` 仍返回 `executionAllowed=false`、`confirmationAvailable=false`。新增独立的 `prepare_daily_workflow` 工具通过签名预览创建整件业务网页确认单，不自动执行。`daily_workflow_status` 按原号找回单据；历史完成状态不宣称已复查当前账务。
- `bookings/prepare` → `bookings/drafts` → 本人 `/operator/daily-workflows/[id]` 页面确认。HTTP 确认入口拒绝 Bearer 和跨源请求；数据库仍校验本人权限、账号、锁内快照及账务。数据库 RPC 本身使用普通认证身份，浏览器交互限制属于应用及连接器边界，不宣称能防止持有同一账号令牌的人直接调用已授权 RPC。
- 同一事务延长住期或记录实际退房日，再登记收款、账本、应收及账号审计；退房创建清洁任务。固定住期的计划退房日不因实际退房被覆盖。任一步错误全部回滚，重复确认仅复核原付款、不再新增付款。
- 数据变化或到期后保留请求号，指定旧确认 ID 重新准备；旧页面作废。服务器发布版本变化要求重新准备。已完成单禁止换号重做，复查发现付款或审计变化不返回成功。
- 迁移 `20260923080038_operator_daily_workflow.sql` 为增量私有表及受限函数，不重写历史业务记录。服务器必须启用确认且数据库协议为 1，连接器才提供组合确认；旧服务不开放此能力。

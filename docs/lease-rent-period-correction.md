# 长租历史租金账期更正

入口：管理员在长租合同详情的“财务记录”中选择“更正租金账期”。中法页面均可使用，其他角色不显示入口；服务端及数据库仍独立校验管理员身份与项目访问范围。

本功能不修改原收款金额、币种、历史汇率、付款日期、付款方式、收据号、客户、押金或正式合同期限，也不代表收到一笔新款。

## 支持的安全范围

- 生效且已起租的合同，当前只有一笔明确的 `lease_rent` 收款及唯一足额结清租金账单。
- 操作人明确选择原收款和原已结账单，填写该笔真实缴至日期和更正依据。
- 旧后续账单必须是与原已缴至日期直接对应的、从未核销或分配过收款的自动生成账单。
- 多笔收款、退款、部分核销、其他手工或待核账单、跨合同分配等均拒绝，不能用此入口批量改账。

确认时，单一数据库事务校验完整账务快照，保留旧自动账单但标记取消，更正合同已缴至日期，为原已结账单保存确认过的覆盖截止日，生成新的下一期应收，并写入前后快照和操作依据。只确认截止日时，覆盖起日留空，不虚构日期。

## 历史更正与新实收必须区分

例如原收款更正为缴至6月30日，另一次实际现金收款缴至7月31日：先完成原账期更正，再从“新增记录”登记后一笔实际收款及其真实日期、金额、方式。更正本身绝不新增收款。

确认过的覆盖截止日优先于账单到期日参与租金累计计算，避免晚缴的旧月租被重复抵扣新月欠租。

## 防重复与发布

- 请求号与内容指纹保存在当前浏览器会话，不保存财务表单内容；失败结果未知时冻结表单，只能以原内容、原请求号重试。不能换号重录。
- 相同账号、请求号和内容的重复请求返回原结果；内容变化或其他账号复用请求号会拒绝。
- 原收款、合同、应收、分配或流水发生并发变化时拒绝旧快照；任何一步失败均整体回滚。
- 迁移 `20261019140744_lease_rent_period_correction.sql` 仅发布结构与受控函数，不包含任何真实客户的数据修改。未部署迁移前，入口读取会失败关闭，不会直接修改数据库表。
- 应通过正常数据库迁移发布流程安装迁移，禁止使用业务连接的任意SQL或服务角色代替本人操作。代码推送、迁移部署与实际账务更正是三个不同结果，需分别核验。

验证：`npm run validate`、`npm test`、`npx vitest run --config vitest.postgres.config.ts tests/lease-rent-period.native.ts`。原生数据库测试只创建隔离的本机测试库，使用合成数据，不接触生产收款。

## 现状与边界

- `src/app` 为页面/API 路由；`src/features` 按业务域组织；`src/lib` 为基础设施/公共逻辑；`operator-connector` 为独立员工客户端。
- 传统页面继续使用既有 Server Actions；连接器走 operator API；关键财务执行依赖数据库 RPC。两者不必强行使用同一个 HTTP 接口，但必须共享核心事务与约束。
- 旧内嵌工作台保留兼容，不作为新增录入方向；不能仅凭“旧”字删除仍可能使用的入口。
- 本轮热点变化：calendar.tsx 1527 → 883 行，booking-panel.tsx 1261 → 1097 行，leases/actions.ts 987 → 29 行兼容入口。长租实际实现分别为合同 281、收款 188、退租 184、应收服务 195 行；日历纯计算、展示和财务明细独立。订单控制器仍然偏大，不宣称全部热点已经消除。
- 开工时当前代码普通测试为 910 通过、1 跳过；本轮新增模块边界、共享操作词汇、日期/房态、真实财务面板点击、重建与篡改拒绝测试。
- 原始迁移有重复版本与历史漂移；应用结构基线不是完整托管 Supabase 平台备份，也不含客户、账务、Auth 密码或 Storage 文件。
- 不能仅凭测试数量证明架构完美；剩余旧财务入口、数据库安全告警及真实人员试用必须明确记录。

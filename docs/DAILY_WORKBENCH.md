# 日租运营台 · 2026-10-20

## 页面范围

- `/daily-rentals` 与 `/fr/daily-rentals` 使用同一响应式工作台。默认“今日运营”，只显示需要核实、入住、离店交接及保洁；历史收款跟进在“收款”分类完整保留，不挤占当天任务。
- 查空房核对整个住宿区间，最多 62 天。入住日包含、离店日不含；未来固定退房可用于排期，但不是已完成交房。未定离店及逾期未实际退房仍占房；维修、锁房、长租、未启用日租及数据不完整时不宣布可入住。
- 排房桌面 7 天、手机 3 天，住宿夜与预计交接分开。没有已知占用不代表房间已就绪，不做拖拽换房或未经确认的隐式写入。
- 历史住宿按所选区间查询，不含已取消订单；完整收款历史、退款/冲正、同比/环比、严格现金汇总和 CSV 仍在原收款分析页。
- 住客与经办人分别展示。缺少住客姓名时，列表显示明确的“经办 · 姓名”，不把经办人或旧 `customer_id` 冒认住客。
- 订单计费、订单已付记录、已登记付款净额和订单计算待收明确区分；不等同于已核实应收。付款净额仅在所有流水明确为 XOF、汇率为 1 且金额为安全整数时合计；出现原币、缺失证据或溢出显示待核对，不混币加总。两种已付口径不一致时要求核对，不据此改账。

## 读取与写入边界

沿用 `daily_calendar_context_rpc` 的调用人权限/RLS，只读完整窗口；没有新迁移、角色扩权、数据修复或业务记录回填。首屏消费 SSR 窗口，不再主动加载月现金与完整客户目录；日期/楼栋切换、恢复焦点、外部录入及手工刷新重新读取，不使用跨账号缓存。读取失败、范围不匹配和迟到响应不会把旧数据当作当前房态。跨日更新业务日期；用户明确选择的日期区间不被擅自改动。

选中订单/房间后才加载原 `BookingPanel`，先重新读取并校验楼栋、房间和订单。配置房价、出售代管的日租能力、预订日期继续传递；保洁有单独明确确认。实际写入仍复用既有服务端角色守卫、原子 RPC、请求幂等和当前操作账号审计。

- admin、rental_sales：沿用原创建权限；admin 保留历史补录与入住纠正。
- front_desk：原有入住、退房、收款和保洁权限；不能因为新查房入口而获得创建权限。
- finance、boss：订单只读打开，保留收据查看/打印；收款分析只向 admin、finance、boss 开放。

房态复制由用户点击后才写入剪贴板，内容不包含住客姓名、电话、经办人身份或收款记录。房态打印保留。

## 验证边界

普通测试覆盖任务/房量、整段冲突、同日交接、未定/逾期离店、维修锁房、代管、金额口径、角色、SSR、异步竞态、跨日日期和手机排房；原生 PostgreSQL 回归继续验证事务与权限，没有用线上业务写入制造测试记录。

真实浏览器使用现有账号只读检查中法页面、两楼栋、今日任务、查房、排房、历史、收款分析入口及预订表单默认住宿区间；不点击提交。技术检查不等于经办人本人业务验收。发布以本次 Git SHA 的 CI 和 Vercel Ready 为准，不复用历史部署结论。

保守边界：已退房但缺失实际离店日的旧记录仍提示日期核对；本轮不会自动补猜或更改原记录。历史取消订单的现金查询仍由原收款分析承接。

# 日租运营台 · 2026-10-20

## 页面范围

- `/daily-rentals` 与 `/fr/daily-rentals` 使用同一响应式工作台，默认“房态日历”：房间为行、日期为列，先看到完整房态，不自动展开第一笔订单。今日入住、在住、离店与保洁以紧凑事项条辅助，点击只突出对应房间，不隐藏其他房源；六类任务仍在“今日事项”完整保留。
- 查空房核对整个住宿区间，最多 62 天。入住日包含、离店日不含；未来固定退房可用于排期，但不是已完成交房。未定离店及逾期未实际退房仍占房；维修、锁房、长租、未启用日租及数据不完整时不宣布可入住。
- 日历桌面 7/14 天、手机 3 天，真实 `floor_label` 分楼层，未知楼层单列，不从房号猜楼层。房号和日期表头冻结；普通房间行压缩到 40px，触摸设备保留足够点击面积。冲突住宿不覆盖，预计交接、保洁和维护独立标记：无日期重叠时共用空位，确有重叠时才加行。没有已知占用不代表房间已就绪，不做拖拽换房或未经确认的隐式写入。
- 选择订单或日期后才展开详情，关闭或 Escape 恢复完整日历宽度并返回原触发控件；窄屏详情在下方显示。空日期格明确带入所选房间和日期，办理前仍重新核验，不因点格子创建记录。新建预订继续先查房，不自动分配房间。
- 今日统计只在当前读取窗口实际包含今天时展示，其他日期窗口不拼出不完整“今日”数量；今日房态复制同样不使用不覆盖今天的窗口。事项分类不可相加当作总房量。
- 历史住宿按所选区间查询，不含已取消订单；完整收款历史、退款/冲正、同比/环比、严格现金汇总和 CSV 仍在原收款分析页。
- 住客与经办人分别展示。缺少住客姓名时，列表显示明确的“经办 · 姓名”，不把经办人或旧 `customer_id` 冒认住客。
- 订单计费、订单已付记录、已登记付款净额和订单计算待收明确区分；不等同于已核实应收。付款净额仅在所有流水明确为 XOF、汇率为 1 且金额为安全整数时合计；出现原币、缺失证据或溢出显示待核对，不混币加总。两种已付口径不一致时要求核对，不据此改账。

## 读取与写入边界

沿用 `daily_calendar_context_rpc` 的调用人权限/RLS，只读完整窗口；没有新迁移、角色扩权、数据修复或业务记录回填。首屏 SSR 与默认桌面七天窗口一致，避免因为额外第八天导致重复请求；手机三天和手动十四天分别读取精确窗口。不再主动加载月现金与完整客户目录；日期/楼栋切换、恢复焦点、外部录入及手工刷新重新读取，不使用跨账号缓存。读取失败、范围不匹配和迟到响应不会把旧数据当作当前房态。跨日更新业务日期；用户明确选择的日期区间不被擅自改动。

选中订单/房间后才加载原 `BookingPanel`，先重新读取并校验楼栋、房间和订单。配置房价、出售代管的日租能力、预订日期继续传递；保洁有单独明确确认。实际写入仍复用既有服务端角色守卫、原子 RPC、请求幂等和当前操作账号审计。

- admin、rental_sales：沿用原创建权限；admin 保留历史补录与入住纠正。
- front_desk：原有入住、退房、收款和保洁权限；不能因为新查房入口而获得创建权限。
- finance、boss：订单只读打开，保留收据查看/打印；收款分析只向 admin、finance、boss 开放。

房态复制由用户点击后才写入剪贴板，内容不包含住客姓名、电话、经办人身份或收款记录。房态打印保留。

## 验证边界

普通测试覆盖任务/房量、整段冲突、同日交接、未定/逾期离店、维修锁房、代管、金额口径、角色、SSR、异步竞态、跨日日期和手机排房；原生 PostgreSQL 回归继续验证事务与权限，没有用线上业务写入制造测试记录。

真实浏览器使用现有账号只读检查中法页面、两楼栋、今日任务、查房、排房、历史、收款分析入口及预订表单默认住宿区间；不点击提交。技术检查不等于经办人本人业务验收。发布核对本次 Git SHA 的 CI、生产部署成功状态及线上页面，不复用历史部署结论；无法访问平台管理日志时，明确保留该证据缺口。具体检查见 [本次日历验收记录](DAILY_CALENDAR_ACCEPTANCE_20261020.md)。

保守边界：已退房但缺失实际离店日的旧记录仍提示日期核对；本轮不会自动补猜或更改原记录。历史取消订单的现金查询仍由原收款分析承接。

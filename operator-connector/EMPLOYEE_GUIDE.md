# SACSI 员工试用说明

这是外部 Codex 的业务连接器，不是另一套 AI，也不需要 Git、开发仓库或数据库管理员密钥。
0.2.0 支持日租、长租和出售的多行截图收款、租金/物业费分账。安装包标有 `production candidate` 时尚未放行，管理员完成服务器和数据库发布核验后才能用于真实业务；`local` 包只能用于本机模拟测试。

## 共用电脑时先分清两个账号

- Codex 订阅账号负责使用 AI；临时在 Chouke 的电脑和 Codex 中工作是可以的。
- SACSI 登录账号决定业务权限和审计记录。小颖实际录入前，连接器和网页都应登录 `ying@sacsi.com`，不能因为共用 Codex 就沿用 Chouke 的 SACSI 账号。
- `check.cmd` 显示的身份不是本人时，先运行 `logout.cmd`，再由实际操作人运行 `login.cmd`。密码只由本人输入，不发送到对话中。
- 系统只能证明哪个 SACSI 账号执行了操作；多人共用同一 SACSI 账号时，不能自动证明当时坐在电脑前的人是谁。

## 第一次安装（请管理员协助一次）

1. 将完整文件夹放在固定位置，例如桌面“SACSI录入”。不要只复制几个文件。
2. 双击 `setup.cmd`，生成 `codex-mcp-config.txt`。将该文件中的配置段加入 Codex 设置的 `config.toml`，不要覆盖已有配置。已有同名 SACSI 配置时由管理员更新，不能重复粘贴。
3. 重启 Codex。在 MCP 服务器列表中确认 `sacsi_operator` 已连接；本地模拟包名称是 `sacsi_operator_local`，不能混用。
4. 双击 `login.cmd`，本人输入 SACSI 邮箱和密码。密码不会显示，不要发送到 AI 对话。双击 `check.cmd` 检查显示的本人姓名和账号标识。
5. 告诉 Codex：“使用 SACSI 工具检查我的账号，然后查询 11 栋 503 的日租订单，只查询，不入账。”楼栋房号按实际修改。

移动文件夹后必须重新生成配置并更新路径。当前安装步骤不是自动安装；无需放宽 Windows PowerShell 执行策略。

## 小颖：一次截图录入

1. 将真实 Excel 收款截图粘贴给 Codex，说明需要录入哪一笔。
2. 让它先查现有订单、客户和财务信息。没有明确金额单位、房间、日期或订单对应关系时，先问清楚。
3. 核对 Codex 给出的每行金额（XOF 西非法郎）、收款日期、方式、收据号及合同。混合房租/物业费时，它先查询合同单价、物业规则和已收金额，再给出分账建议。例如月租 60 万、物业 4 万，明确六个月合计 384 万时，建议租金 360 万、物业费 24 万。
4. 它会提供待确认链接和请求号。本人打开链接，用与连接器相同的 SACSI 账号登录，核对后确认。
5. 网页明确显示完成才算入账；“待确认”不算。保留请求号供核对审计。不要重复登记同一凭证。

多行截图将出现在一张整批确认页，每个房间分别列出原文、客户、合同、应收账期、分项金额及入账后余额。整批总额必须相等；有冲突时整批停止，不会偷偷忽略问题行。长租“已缴至”是租金覆盖日期，不是收到款的日期，请单独核对。

合同缺失、未开业、免租、汇率不明、已有部分收款、应收未建立或物业规则冲突时，先问清楚，必要时联系 Chucke。系统不会为凑平总额创造收费标准或账单。原 Excel 与凭证保存流程继续保留。

## 黄姐：核对审计

使用本人账号进入 SACSI 的审计日志，按录入账号、请求号或订单查找。核对实际录入人、业务经办人、金额、日期和修改前后记录；两条日志可能分别对应收款及网页确认，不代表两笔收款。若看不到日志，请管理员检查账号权限，不借用他人账号。

## 停电、断网或交接

- 未明确显示成功：保留原截图、请求号、确认链接和报错，交给管理员核查。不要换请求号重新录入。
- 多行批次链接丢失时，告诉 Codex“用 collection_status 查询这个原请求号”，找回原单；`verified=false` 表示尚未核实，不能称已成功入账。
- 确认单失效或账务变化：先重新查询，明确重做原单，沿用请求号。旧链接不能用于新金额。
- 0.4.0 没有离线自动入账/自动补传。准备确认单前会自动加密保存原单；告诉 Codex“列出我的本地待办”，再指定原请求号恢复。服务器记录已完成时不能重录；待确认时找回原链接；未找到时只重新生成原号确认页。
- 完全断网、Codex 也无法对话时，可双击 `capture.cmd`，确认显示的是自己的账号标识，输入简短凭证说明；它只保存本地待办，不识别图片、不连接模型、不入账。截图另存。`pending.cmd` 可查看请求号。
- 换人接手不能沿用原人的确认链接直接付款；先查原单是否已经完成，由管理员处理交接，防止重复入账。
- 共用电脑离开前双击 `logout.cmd`，网页也要退出。不同人不能共用同一个 SACSI 登录。
- `connector_busy_or_stale_lock`：先关闭已经退出或卡住的连接器操作，联系管理员核查。0.4.0 的 `recover-lock.cmd` 只会恢复进程确已退出的锁，运行中或旧格式不会被删除；恢复锁不代表业务没执行，仍须查原待办。

待办状态说明：待补信息＝只有凭证说明；准备中/结果未知＝需联网核对；待网页确认＝还不能当作已收款；服务器曾记录完成＝原单勿重录，不代表重新核对了之后所有账务。无需额外逐笔手工标记“已复核”。

换电脑、Windows 账号或回滚软件前请管理员协助。不要删除 `%LOCALAPPDATA%\SACSI`，不要把加密待办当成可跨电脑还原的备份。共用同一 SACSI 账号仍无法自动区分实际操作者。

## 试用反馈

请记录：本人账号、操作时间、做了什么、预期结果、实际结果、请求号、报错截图。不要发送密码或访问令牌。一次真实操作顺畅并不代表所有异常场景都已验收。
# 0.5.0 新操作说明（待发布）

除截图收款外，可让助手准备预订、入住、改期改价、房号纠正、取消、冲正或实际退款。先核对预览，再用本人 SACSI 账号打开确认页；助手不会代为确认。

“原房号录错”与“实际搬到另一间房”不同，本版支持前者的整单纠正，后者先联系 Chucke。“冲正”与“实际退款”也不同：退款页面只记录已经退给客户的钱，并不替你转账。不清楚金额、原因、日期或退款方式时先问清楚。

新功能上线前，本机旧版连接器仍按原范围工作。共用电脑换人时，连接器和网页都要登录实际操作人的账号。
